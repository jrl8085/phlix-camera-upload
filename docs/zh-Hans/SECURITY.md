# 安全

Phlix Camera Upload 是相机上传功能的助手，而相机上传是 Phlix App 的一项测试版功能。本页介绍它的安全性。如需设置，请按照设置指南操作：<https://phlixapp.com/camera-upload/>

## 报告问题

请私下报告安全问题，不要通过公开的 issue 报告。

1. 打开本仓库的 Security（安全）标签页：<https://github.com/jrl8085/phlix-camera-upload/security>
2. 选择 Report a vulnerability（报告漏洞）。
3. 说明你发现了什么、如何复现，以及你使用的助手版本。运行 `docker exec phlix-camera-upload python -m phlix_upload version` 命令即可显示版本号。

在修复发布之前，GitHub 只让你和维护者看到这份报告。

## 适用范围

- 助手：本仓库 `phlix_upload/` 文件夹中的程序。
- 它的 Docker 镜像：`ghcr.io/jrl8085/phlix-camera-upload`。
- 用来安装它的文件：`install.sh`、`docker-compose.yml` 和 Unraid 模板。

修复会发布到最新的 1.x 镜像，也就是标签 `:1`。

以下不在此范围内：Phlix App、网站 phlixapp.com、Plex Media Server 和 Docker。关于 App 和网站的问题，请通过 <https://phlixapp.com/support/> 联系。

## 助手的安全设计

助手是为家庭网络设计的，不应该能从互联网访问。

**它只负责接收。**

- 助手没有任何一个地址能把已存储的文件读回去。已配对的手机只能向上传文件夹添加文件，不能做别的事。
- 一部手机无法列出另一部手机发送过的内容。
- 状态页面和健康检查地址不会显示配对码、令牌、设备名称或文件名。

**连接。**

- 助手通过 HTTPS 提供服务，使用 TLS 1.2 或更高版本。
- 首次启动时，它会生成自己的证书。App 在配对时会记住这张证书的指纹，此后只与出示这张证书的服务器通信。

**配对。**

- Plex 服务器的所有者通过 Plex 配对。App 会发送一个短期有效的 Plex 登录凭据。助手把它出示给自己找到的那台 Plex 服务器，所用的两个地址只有所有者才能读取，并且不跟随任何重定向。助手从不存储这个登录凭据，也从不把它写入日志。
- 助手自动查找 Plex 时会先尝试 https，以免登录凭据在传输途中被人读取。它不检查 Plex 的证书。
- 如果 Plex 无需登录就会响应这两个地址，那么登录凭据就证明不了任何事。这时助手会拒绝通过 Plex 配对。
- 其他人都需要配对码。助手用安全的随机源生成配对码，并以恒定时间进行比较。
- 同一个地址每分钟最多有五次错误尝试。错误尝试是指输错配对码，或者 Plex 登录凭据被拒绝。
- 如果所有地址在十分钟内合计输错 200 次配对码，所有人的配对码配对都会暂停。通过 Plex 配对绝不会因此暂停。

**令牌。**

- 每部已配对的手机都会获得一个自己的 256 位随机令牌。
- 助手只存储令牌的 SHA-256 哈希值，并以恒定时间比较哈希值。即使有人复制了助手的数据库，也无法用它上传。
- 取消配对会立即使该手机的令牌失效。仍处于配对状态的设备再次配对时，它之前的令牌会失效，日志中也会记录这一点。

**文件。**

- 助手只接受照片和视频文件类型，其他一律拒绝，因此即使令牌被盗，也无法用它把程序放到服务器上。
- 手机发送的每个文件名和文件夹名，在成为路径的一部分之前都会经过清理。任何内容都不会写到上传文件夹之外。
- 文件总是以尚未被占用的名称创建。已有的内容绝不会被覆盖。
- 助手会核对手机随每次上传发送的 SHA-256，并丢弃损坏的上传。
- 上传有大小限制。助手会让磁盘保留一部分可用空间，并把仍在传输中的上传计算在内，因此即使同时进行多个上传，也无法占满磁盘。

**连接数。**

- 助手允许同一个地址同时建立 24 个连接，总共最多 96 个。
- 新连接有 10 秒时间完成 TLS 握手，有 20 秒时间发送首个请求。此后，连接最多可以静默 75 秒。

**程序本身。**

- 助手以 root 身份启动，只是为了切换到上传文件夹的所有者，或者切换到 `PUID` 和 `PGID` 指定的用户。在此之前，它不提供任何服务。
- Compose 文件以 `no-new-privileges` 启动它。
- 助手只使用 Python 标准库，不依赖其他任何库。镜像是 Alpine 版的官方 Python 镜像，只额外添加了一个软件包：`openssl`。
- 助手不保存任何 Plex 密码或 Plex 登录凭据。它没有设置页面，也没有登录页面。

## 已知并接受的情况

这些是有意的取舍，不是缺陷。超出这些范围的问题，请报告。

1. **同一个助手的手机属于同一个家庭**。相同的文件只存储一次。因此，已配对的手机可以得知另一部手机已经上传过某个文件，以及这个文件有多大。前提是它持有同一个文件，或者知道该文件的 SHA-256。它无法得知文件存放在哪里，也无法读取文件。
2. **网络中的任何人都能打开状态页面**。页面显示助手的版本、磁盘的大小及其可用空间、是否找到了 Plex 及其版本、已配对的设备数量，以及已存储的文件数量和总大小。App 首先访问的地址 `/api/v1/hello` 还会提供助手的名称和 Plex 服务器的标识符。这些都不会显示设备名称、文件名、令牌或配对码。
3. **配对码是家庭内部的秘密**。设备的 ID 是一个只有该设备和助手知道的随机值。同时掌握配对码和这个 ID 的人，就能以该设备的身份配对。有人离开这个家庭时，请用 `new-code` 命令更换配对码。
4. **未设置 `PLEX_URL` 时，助手会信任以 Plex 身份响应的对象**。它会查看 Docker 主机、容器的网关、`127.0.0.1` 和名为 `plex` 的容器，并采用首个像 Plex 那样响应的对象。设置 `PLEX_URL` 即可把它固定到你的服务器。
5. **如果上传文件夹的所有者是 root，助手会一直以 root 身份运行**。它会在日志和 `doctor` 中说明这一点。
6. **繁忙的网络可能让助手一直忙于应付**。一个地址仍然可以占用 24 个连接。在恶意的网络中，没有什么能免受这种影响。这是为家庭网络设计的助手，不是为互联网设计的。

## 安全审查做过的攻击测试

助手首次发布之前，经过了一次安全审查的攻击测试。以下各项都经受住了考验：

- 针对手机发送的每个字段的路径遍历和异常名称；
- 仅限照片和视频文件类型的限制，以及不覆盖任何文件的规则；
- 令牌和配对码的比较；
- 请求的分帧，以及针对每个存储值的 SQL 注入。
