# Phlix Camera Upload

**ベータ版**。これは、iPhone・iPad用アプリ[Phlix](https://phlixapp.com)のベータ機能「カメラアップロード」のうち、サーバー側を担う部分です。もう一方の部分は、Phlix 1.0.21以降の「設定」>「カメラアップロード」にあります。このバージョンはApp Storeで配信されています。

**画像付きのセットアップガイド：<https://phlixapp.com/camera-upload/>**

このページで紹介するプログラムを「ヘルパー」と呼びます。ヘルパーは、PhlixがiPhoneやiPadから自宅のネットワーク経由でアップロードする写真とビデオを受け取り、Plexの写真ライブラリのフォルダに書き込みます。Plex Media Serverと同じマシン上のDockerで動作します。同期サービスでもクラウドサービスでもなく、ファイルを削除することも、ファイルを送り返すこともありません。

## できること（ベータ版）

カメラアップロードはベータ版で、アプリにもBETAと表示されています。替えのきかないものは、ご自身でも別にバックアップを保管してください。下の2つの一覧に、ベータ版でできることとできないことをまとめています。セットアップガイドにも同じ一覧があります：<https://phlixapp.com/camera-upload/#beta>

### ベータ版でできること

- iPhoneやiPadの写真ライブラリにある写真とビデオを、自分のサーバー上にあるPlexの写真ライブラリのフォルダにバックアップします。
- 何かをオンにする前に、Phlixはヘルパーがネットワーク上にあることを確認します。確認する場所は、Plexサーバーのアドレスのポート7459か、自分で入力したアドレスです。ヘルパーが見つからない場合、カメラアップロードはオフのままで、Phlixがその理由を表示します。
- Plexサーバーの所有者は、コードなしでペアリングできます。それ以外の人は、ヘルパーのペアリングコードを入力します。
- アップロードするのは自宅のWi-Fi上だけです。自宅のWi-Fiとは、ペアリングしたときにデバイスが接続していたネットワーク、または自分で追加したネットワークです。追加するには、そのネットワークに接続して「カメラアップロード」画面を開き、「このネットワークを自宅に設定」を選びます。
- 接続は暗号化されます（HTTPS）。Phlixが通信するのは、ペアリング時に証明書を確認したヘルパーだけです。
- 接続に問題がなければ、「カメラアップロード」画面に緑の点と「（ヘルパー名）に接続済み」が表示されます。全体のうち何件がバックアップ済みか、あと何件がバックアップ待ちかも表示されます。アップロード中の項目、最近バックアップした項目、バックアップできなかった件数も表示されます。すべてのバックアップが終わると、「すべてバックアップ済み」と表示されます。
- すべてのバックアップが終わったときに、Phlixから通知を受け取ることもできます。「バックアップ完了時に通知」をオンにしてください。
- バックアップする項目は自分で選べます。「ビデオを含める」は最初はオン、「スクリーンショットを含める」は最初はオフです。「バックアップ対象」は「このデバイスのすべて」か「新しい写真のみ」に設定します。
- Phlixを開いているあいだは、新しい写真が自動的にアップロードされます。Phlixを閉じているときは、iOSが許可する短い時間ごとに少しずつ進みます。その多くはデバイスの充電中です。
- 写真はそれぞれ、その時点で「写真」に表示されている状態でアップロードされます。編集した写真は、編集後の状態でアップロードされます。Live Photosは静止画としてアップロードされます。
- サーバーでは、デバイスごとに専用のフォルダが作られ、その中に年ごと、月ごとのフォルダができます。ファイルの名前と日付はそのまま保たれます。2台のデバイスから同じ写真が届いた場合、保存されるのは1回だけです。上書きされることは一切ありません。
- Plexアカウントがサーバーの所有者である場合は、写真が届くとPhlixがPlexにスキャンを依頼するので、写真がPlexに表示されます。
- デバイス上のものを削除したり変更したりすることは一切ありません。一方向のコピーです。
- 最初の100件のアップロードは無料です。残りはPhlix Proでアップロードされます。
- ヘルパーは、Intel、AMD、Armに対応した1つのDockerコンテナです。読み取り専用のステータスページと、インストールを確認して問題の直し方を示す`doctor`コマンドがあります。アカウントもクラウドサービスもありません。

### ベータ版でできないこと

- 外出先ではアップロードしません。モバイルデータ通信や、外部から自宅へのVPN経由でもアップロードしません。外出先では、ヘルパーを探すことさえしません。
- 同期ではありません。スマートフォンで写真を削除しても、サーバー上のコピーは残ります。また、サーバーからスマートフォンに何かが戻ってくることもありません。
- Live Photosのビデオ部分、非表示の写真、共有アルバム、コンピュータから同期した写真はアップロードしません。
- ヘルパーがPlexとは別のマシンや別のポートにある場合、ヘルパーを自動では見つけられません。その場合は、アドレスを一度入力します。
- Phlixを閉じているときは、iOSが許可したときにアップロードされます。ライブラリが大きい場合、バックグラウンドでは数日かかります。
- 対応しているのはiPhoneとiPadだけです。自宅のネットワークでは、`192.168.1.10`のようなIPv4アドレスが使われている必要があります。
- ベータ版です。替えのきかないものは、ご自身でも別にバックアップを保管してください。

## 必要なもの

- Plex Media ServerとDockerが動作するコンピュータまたはNAS。Dockerはバージョン20.10以降で、Docker Composeのバージョン2（`docker compose`コマンド）が必要です。
  - Ubuntuで`sudo apt install docker.io`を使ってDockerをインストールした場合は、`sudo apt install docker-compose-v2`でComposeを追加します。このパッケージはUbuntu 22.04以降にあります。
  - Snap版のDockerではヘルパーを起動できません。Ubuntu Serverは、インストール中にこのSnapを勧めてきます。確認するには、`snap list docker`を実行します。dockerが一覧に表示された場合は、[Docker Composeに「bind source path does not exist」と表示される](#docker-composeにbind-source-path-does-not-existと表示される)を参照してください。
- Plexの写真ライブラリ。
- iPhoneまたはiPadにインストールされたPhlix 1.0.21以降。確認するには、Phlixの「設定」を開きます。1.0.21以降には、BETAと表示された「カメラアップロード」の行があります。このバージョンはApp Storeで配信されています。
- スマートフォンとサーバーが同じ自宅のネットワークにあること。

イメージは、64ビットのIntelとAMD、64ビットのArm、32ビットのArm（ARMv7）で動作します。イメージにはそれぞれのバリアントが1つずつ含まれており、Dockerがお使いのマシンに合うものを自動で選びます。[GitHubのイメージのページ](https://github.com/jrl8085/phlix-camera-upload/pkgs/container/phlix-camera-upload)には`unknown/unknown`も表示されますが、これはバリアントではありません。イメージがどのようにビルドされ、何が含まれているかの記録です。

## インストール

Plex Media Serverが動作しているマシンにインストールします。そのマシンにはDockerが必要です。

最初に1つだけ決めておくことがあります。写真の保存先となるアップロードフォルダです。このフォルダは、Plexの写真ライブラリのどれかに含まれているフォルダの中に置く必要があります（例：`/mnt/media/Photos/Camera Uploads`）。ライブラリに含まれるフォルダは、Plexの「設定」>「管理」>「ライブラリ」>「ライブラリを編集」>「フォルダを追加」で確認できます。Plex自体をDockerで動かしている場合は、Plexコンテナ内でのパスではなく、サーバー上でのフォルダのパスを使ってください。

次に、3つの方法から1つを選びます。

### 1. コマンド1つで

```sh
curl -fsSL https://raw.githubusercontent.com/jrl8085/phlix-camera-upload/main/install.sh | sh
```

インストーラはアップロードフォルダの場所を尋ね、フォルダがなければ作成します。ホームフォルダ内の`phlix-camera-upload`に`docker-compose.yml`を書き込み、ヘルパーを起動して確認し、次にすることを案内します。アップデートするときは、もう一度実行します。

LinuxとDocker DesktopのあるMacで使えます。Unraid、TrueNAS SCALE、QNAPでは、代わりに[その他のプラットフォーム](#その他のプラットフォーム)の手順に従ってください。

質問の答えをあらかじめ指定するには、次のようにします。

```sh
curl -fsSL https://raw.githubusercontent.com/jrl8085/phlix-camera-upload/main/install.sh | sh -s -- --photos "/mnt/media/Photos/Camera Uploads" --yes
```

`--photos`と`--yes`を付けると、インストーラは何も尋ねず、アップロードフォルダがなければ作成します。あとで更新するときは、どちらも付けずに実行してください。そうすれば、インストーラは`docker-compose.yml`をそのまま残します。付けて実行すると、新しい`docker-compose.yml`が書き出されることがあり、そこに引き継がれるのはアップロードフォルダ、ポート、`PLEX_URL`、`PUID`、`PGID`だけです。古いファイルは新しいファイルの隣に残ります。

`--dry-run`を付けると実行内容を確認でき、`--help`を付けるとすべてのオプションを確認できます。インストーラが`sudo`を使うことはありません。サーバーのDockerにそれが必要な場合は、インストーラがその旨を伝えて停止します。

### 2. AIアシスタントに任せる

アシスタントは、ヘルパー自身のフォルダ以外を変更する前に必ず確認を求め、Plexを変更することはありません。サーバー上か、SSHでサーバーに接続できるコンピュータで実行してください。

**Claude Code**：セッションで、次の2行を入力します。

```
/plugin marketplace add jrl8085/phlix-camera-upload
/plugin install phlix-camera-upload@phlix
```

シェルから行う場合は、`claude plugin marketplace add jrl8085/phlix-camera-upload`を実行してから`claude plugin install phlix-camera-upload@phlix`を実行します。

そのあと「このサーバーにPhlix Camera Uploadをセットアップして」と伝えるか、`/phlix-camera-upload:phlix-camera-upload-setup`と入力します。

**プラグインシステムを使わないClaude Code**：スキルを自分のスキルフォルダにコピーします。

```sh
mkdir -p ~/.claude/skills/phlix-camera-upload-setup
curl -fsSL https://raw.githubusercontent.com/jrl8085/phlix-camera-upload/main/skills/phlix-camera-upload-setup/SKILL.md -o ~/.claude/skills/phlix-camera-upload-setup/SKILL.md
```

再起動は必要ありません。スキルが表示されない場合は、`/reload-skills`と入力します。そのあと「このサーバーにPhlix Camera Uploadをセットアップして」と伝えるか、`/phlix-camera-upload-setup`と入力します。

**Claudeアプリ（claude.aiとClaude Desktop）**：[phlix-camera-upload-setup.zip](https://github.com/jrl8085/phlix-camera-upload/releases/latest/download/phlix-camera-upload-setup.zip)をダウンロードします。Claudeで、Customize > Skills（カスタマイズ > スキル）に進み、+、Create skill（スキルを作成）、Upload a skill（スキルをアップロード）の順に選んで、ZIPファイルを選択します。このスキルを使うには、Code execution and file creation（コードの実行とファイルの作成）をオンにしておく必要があります。この方法では、Claudeからサーバーにはアクセスできません。Claudeが実行するコマンドを1つずつ示すので、コマンドが出力した内容を貼り付けてください。

**その他のアシスタント**（ChatGPT、Gemini、Cursor、Copilot、ローカルモデルなど）：[SETUP-WITH-AI.md](../../SETUP-WITH-AI.md)を渡して、「SETUP-WITH-AI.mdに従って」と伝えます。このファイルは英語ですが、AIアシスタントはどの言語でやり取りしていても、この手順に従って作業できます。ファイルは次のコマンドでダウンロードできます。

```sh
curl -fsSLO https://raw.githubusercontent.com/jrl8085/phlix-camera-upload/main/SETUP-WITH-AI.md
```

### 3. Docker Composeを使って手動で

この手順はLinux向けです。Unraid、Synology、TrueNAS SCALE、QNAP、Docker Desktopの場合は、先に[その他のプラットフォーム](#その他のプラットフォーム)をお読みください。

1. 写真を所有しているユーザーとして、アップロードフォルダを作成します。ヘルパーは、このフォルダの所有者としてファイルを書き込みます。

   ```sh
   mkdir "/mnt/media/Photos/Camera Uploads"
   ```

   `mkdir`で`Permission denied`と表示された場合は、自分のユーザーではライブラリのフォルダに書き込めない可能性があります。たとえば、そのフォルダの所有者がrootか、Plex Media Serverを実行するユーザーであるplexになっている場合です。`sudo`でフォルダを作成し、1つ上のフォルダと同じ所有者にします。例のパスは自分のパスに置き換えてください。

   ```sh
   sudo mkdir "/mnt/media/Photos/Camera Uploads"
   sudo chown --reference="/mnt/media/Photos" "/mnt/media/Photos/Camera Uploads"
   ```

2. ヘルパー用のフォルダを作成します。

   ```sh
   mkdir phlix-camera-upload
   ```

3. そのフォルダに移動します。

   ```sh
   cd phlix-camera-upload
   ```

4. Composeファイルをダウンロードします。

   ```sh
   curl -fsSLO https://raw.githubusercontent.com/jrl8085/phlix-camera-upload/main/docker-compose.yml
   ```

5. テキストエディタで`docker-compose.yml`を開き、1行だけ変更します。`source: /CHANGE/THIS/Photos/Camera Uploads`という行を探します。この行は、`CHANGE THE NEXT LINE`というコメントのすぐ下にあります。`/CHANGE/THIS/Photos/Camera Uploads`を自分のアップロードフォルダに置き換えて、ファイルを保存します。

6. ヘルパーを起動します。初回は、Dockerがイメージをダウンロードします。

   ```sh
   docker compose up -d
   ```

7. 問題がないかヘルパーに確認します。出力は`Nothing needs fixing.`で終わるはずです。

   ```sh
   docker exec phlix-camera-upload python -m phlix_upload doctor
   ```

8. 自宅のネットワーク上の別のデバイスで、ブラウザから`https://SERVER:7459`を開きます。`SERVER`はサーバーのアドレスに置き換えます（例：`https://192.168.1.10:7459`）。アドレスを調べるには、Linuxでは`hostname -I`、Macでは`ipconfig getifaddr en0`を実行します。Windowsでは`ipconfig`を実行し、「IPv4 アドレス」（英語版ではIPv4 Address）の行を見ます。ブラウザに証明書の警告が表示されますが、これは想定どおりです。家庭用のサーバーには認証局が証明できる公開の名前がないため、ヘルパーは自分で証明書を作成します。ブラウザは、そのように作られた証明書にはすべて警告を表示します。「詳細設定」（Advanced）または「詳細を表示」（Show Details）を選んでから、先に進んでください。ページに`Upload folder: Ready`と`Plex Media Server: Found`と表示されるはずです。

## インストールのあとで

1. Plexで、「設定」>「ライブラリー」>「ライブラリーを自動的にスキャンする」をオンにします。Plexはスキャンしたあとでないと新しいファイルを表示しません。また、この設定は初期状態ではオフになっています。
2. [iPhoneを接続します](#iphoneを接続する)。

うまくいかない場合は、まず[トラブルシューティング](#トラブルシューティング)をご覧ください。アプリがヘルパーを見つけられない場合は、[NETWORKING.md](NETWORKING.md)をお読みください。

## iPhoneを接続する

Phlix 1.0.21以降が必要です。アプリでは、カメラアップロードにBETAと表示されています。先に[ベータ版でできること](#ベータ版でできること)と[ベータ版でできないこと](#ベータ版でできないこと)をお読みください。

1. iPhoneまたはiPadを自宅のWi-Fiに接続します。
2. Phlixを開き、「設定」>「カメラアップロード」に進みます。
3. 「ヘルパーを探す」をタップしてから、「ネットワークを確認」をタップします。
4. Phlixに「ヘルパーが見つかりました」と表示されたら、このデバイス用のフォルダ名を決めて「接続」をタップします。
5. 「このデバイスのすべて」または「新しい写真のみ」を選び、「カメラアップロードをオンにする」をタップします。続いて、Phlixに写真の読み取りを許可するかどうかをiOSが確認するので、「フルアクセス」を選択します。

Phlixは、Plexサーバー自体のアドレスのポート7459でヘルパーを探します。ヘルパーが見つかるまで、何もオンにならず、何もアップロードされません。スマートフォンのペアリングが済むと、画面に緑の点と「（ヘルパー名）に接続済み」が表示されます。Phlixに「ヘルパーが見つかりません」と表示された場合、カメラアップロードはオフのままです。その場合は、Phlixに表示される欄にヘルパーのアドレス（例：`192.168.1.10:7459`）を入力し、「このアドレスを確認」をタップします。ほかに確認することは、[NETWORKING.md](NETWORKING.md)で説明しています。

### ペアリング

- **Plexサーバーの所有者の場合**：Phlixはコードなしでペアリングします。アプリは、有効期間の短いPlexトークンをヘルパーに送ります。ヘルパーは、そのトークンがサーバーの所有者のものかどうかをPlexサーバーに問い合わせ、そのあとトークンを破棄します。
- **それ以外の人**（自分のPlexアカウントを持つ家族など）は、ペアリングコードを入力します。

ペアリングコードは、次の2か所で確認できます。

- ヘルパーのログ。ヘルパーが起動するたびに出力されます。`docker logs phlix-camera-upload`を実行し、`Pairing code:`の行を探します。
- 次のコマンドの出力。

  ```sh
  docker exec phlix-camera-upload python -m phlix_upload code
  ```

コードでは、大文字か小文字か、スペースやハイフンがあるかどうかは関係ありません。

## 設定画面はあえてありません

ヘルパーには設定画面もサインインページもありません。これは意図的なものです。設定を変更できるページがあれば、それだけ守るべきものが増えるからです。ヘルパーの設定は[設定](#設定)にある環境変数で行い、ペアリングはスマートフォンから行います。ステータスページは`https://SERVER:7459`の1つだけで、読み取り専用であり、秘密の情報は何も表示しません。管理作業は`python -m phlix_upload ...`コマンドで行います。[管理コマンド](#管理コマンド)をご覧ください。

## その他のプラットフォーム

ここでは、上の手順と異なる点だけを説明します。

### Unraid

UnraidにはDocker Composeがないため、コマンド1つで行うインストーラは使えません。テンプレートを使ってください。

1. Plexの写真ライブラリに含まれている共有フォルダの中に、アップロードフォルダを作成します（例：`/mnt/user/Photos/Camera Uploads`）。
2. Unraidのターミナルを開きます。
3. テンプレートをダウンロードします。

   ```sh
   wget -O /boot/config/plugins/dockerMan/templates-user/my-phlix-camera-upload.xml https://raw.githubusercontent.com/jrl8085/phlix-camera-upload/main/unraid/phlix-camera-upload.xml
   ```

4. Dockerタブを開き、Add Container（コンテナを追加）を選びます。
5. Template（テンプレート）の一覧で`phlix-camera-upload`を選びます。
6. Photosにアップロードフォルダを設定します。
7. Apply（適用）を選びます。

このテンプレートでは、ヘルパーはUnraidの標準のユーザーとグループ（`PUID` 99と`PGID` 100）で動作します。ステータスページを開くには、コンテナのアイコンでWebUIを選びます。

Network TypeはBridgeのままにしてください。コンテナに専用のアドレスを割り当てる場合（Custom: br0）は、[NETWORKING.md](NETWORKING.md)の方法Dをお読みください。

Plexをコンテナで動かしている場合は、Plexコンテナ側のパスと照らし合わせてください。アップロードフォルダは、Plexコンテナに割り当てられているフォルダの中にある必要があります。

### Synology（Container Manager）

Container Managerを使うにはDSM 7.2以降が必要です。また、SynologyがContainer Managerを提供しているのは一部の機種だけです。対応機種は、SynologyのContainer ManagerのページでApplied Models（対応機種）として記載されています：<https://www.synology.com/en-global/dsm/packages/ContainerManager>。お使いの機種が記載されていない場合、この手順はそのNASでは使えません。代わりに、自宅の別のコンピュータでヘルパーを動かしてください。[NETWORKING.md](NETWORKING.md)の「Plexとは別のマシンで動くヘルパー」をお読みください。

1. File Stationで、Plexの写真ライブラリが使っている共有フォルダの中にアップロードフォルダを作成します。
2. File Stationで、ヘルパー用のフォルダを作成します（例：`docker/phlix-camera-upload`）。
3. Container Managerを開き、Project（プロジェクト）、Create（作成）の順に選びます。
4. 名前に`phlix-camera-upload`と入力し、パスには手順2のフォルダを選びます。
5. ソースとしてCreate docker-compose.yml（docker-compose.ymlを作成）を選び、[docker-compose.yml](../../docker-compose.yml)の内容を貼り付けます。
6. 変更が必要な1行を、アップロードフォルダのフルパスに書き換えます（例：`/volume1/photo/Camera Uploads`）。フルパスは、File StationのProperties（プロパティ）にLocation（場所）として表示されます。
7. ウィザードを完了します。Container Managerがイメージをダウンロードし、ヘルパーを起動します。

DSMのファイアウォールがオンの場合は、Control Panel > Security > Firewall（コントロールパネル > セキュリティ > ファイアウォール）でTCPポート7459を許可します。

ヘルパーがアップロードフォルダに書き込めないとステータスページに表示される場合は、Control Panel > Shared Folder > Edit > Permissions（コントロールパネル > 共有フォルダ > 編集 > 権限）を開きます。アップロードフォルダを所有するユーザーに、Read/Write（読み取り/書き込み）の権限を与えてください。

管理コマンドを実行するには、まずSSHをオンにします。Control Panel > Terminal & SNMP > Terminal（コントロールパネル > 端末とSNMP > ターミナル）で、Enable SSH service（SSHサービスを有効にする）にチェックを入れ、Apply（適用）を選びます。次に、administratorsグループに属するDSMユーザーとして`ssh NAME@SERVER`でサインインし、コマンドの前に`sudo`を付けます。SSHが不要になったら、再びオフにしてください。

ペアリングコードはヘルパーのログにも表示されるので、SSHを使わずに確認できます。Container ManagerでContainer（コンテナ）を開き、`phlix-camera-upload`を選択して、Action > Details（操作 > 詳細）を選び、Log（ログ）タブを開きます。`Pairing code:`という行を探してください。

### TrueNAS SCALE

この手順にはTrueNAS SCALE 24.10以降が必要です。ここではコマンド1つで行うインストーラは使わず、アプリの管理はTrueNASに任せてください。

1. Plexの写真ライブラリが使っているデータセットの中に、アップロードフォルダを作成します。
2. Apps > Discover Apps（アプリ > アプリを探す）に進み、3つの点のメニューを開いて、Install via YAML（YAMLでインストール）を選びます。
3. 名前に`phlix-camera-upload`と入力し、[docker-compose.yml](../../docker-compose.yml)の内容を貼り付けます。
4. 写真フォルダの行を、アップロードフォルダのフルパスに書き換えます（例：`/mnt/tank/media/Photos/Camera Uploads`）。
5. `./config:/config`をフルパスに書き換えます（例：`/mnt/tank/apps/phlix-camera-upload:/config`）。TrueNASには、ファイルの隣にフォルダがありません。
6. Save（保存）を選びます。

管理コマンドを実行するには、System > Shell（システム > シェル）を開き、コマンドの前に`sudo`を付けます。

### QNAP（Container Station）

この手順には、QTS 5.1またはQuTS hero h5.1以降で動作するContainer Station 3が必要です。ここではコマンド1つで行うインストーラは使わず、ヘルパーの管理はContainer Stationに任せてください。

1. App CenterでContainer Stationをインストールし、開きます。
2. File Stationで、Plexの写真ライブラリが使っている共有フォルダの中にアップロードフォルダを作成します。フルパスは`/share/`と共有フォルダの名前で始まります（例：`/share/Multimedia/Photos/Camera Uploads`）。Plexでライブラリのフォルダが`/share/CACHEDEV1_DATA/Multimedia/Photos`のように表示される場合も、それは同じフォルダなので、そのパスでもかまいません。
3. File Stationで、ヘルパー自身のデータ用のフォルダも作成します。たとえば、Containerという名前の共有フォルダの中に`phlix-camera-upload`を作ります。その場合、フルパスは`/share/Container/phlix-camera-upload`になります。
4. Container Stationで、上部にあるExplore（探索）の横の矢印をクリックし、Create Application（アプリケーションの作成）を選びます。または、Applications（アプリケーション）に移動して、Create（作成）を選びます。
5. 名前に`phlix-camera-upload`と入力し、[docker-compose.yml](../../docker-compose.yml)の内容を貼り付けます。
6. 変更が必要な1行を、アップロードフォルダのフルパスに書き換えます。`./config:/config`は、手順3のフォルダに書き換えます（例：`/share/Container/phlix-camera-upload:/config`）。どちらのパスも`/share/`で始まります。
7. Validate（検証）、Create（作成）の順に選びます。Container Stationがイメージをダウンロードし、ヘルパーを起動します。

ヘルパーは、アップロードフォルダの所有者としてファイルを書き込みます。QNAPでは、adminという名前のアカウントがスーパーユーザー（root）です。adminとしてアップロードフォルダを作成した場合、ファイルの所有者はadminになります。このときログには`Running as root`と表示され、`doctor`には`The helper runs as root`というNOTEが表示されます。これは問題ありません。Plexは引き続きファイルを読み取れます。ファイルの所有者を別のユーザーにするには、そのユーザーでQTSにサインインした状態でアップロードフォルダを作成してください。通常は、フォルダの所有者がそのユーザーになり、写真の所有者も同じになります。

管理コマンドを実行するには、Container StationでContainers（コンテナ）を開き、`phlix-camera-upload`を選択してExecute（実行）を選びます。コマンドは先頭の`docker exec phlix-camera-upload`を除いた形で入力し（例：`python -m phlix_upload doctor`）、実行します。ペアリングコードはコンテナのLogs（ログ）タブにも表示されます。`Pairing code:`という行を探してください。

このREADMEで`docker-compose.yml`を変更して`docker compose up -d`を実行するよう書かれている箇所では、代わりにContainer StationでApplications（アプリケーション）を開きます。`phlix-camera-upload`を選択し、Edit（編集）の横の矢印をクリックして、Recreate（再作成）を選びます。そこで内容を変更し、Update（更新）を選びます。

QuFirewallがオンで、アプリがヘルパーを見つけられない場合は、自宅のネットワークからのTCPポート7459を許可します。[NETWORKING.md](NETWORKING.md)の「サーバーのファイアウォール」をお読みください。

### 一般的なLinux

違いはありません。注意点が2つあります。

- Dockerが「permission denied」と返す場合は、各`docker`コマンドの前に`sudo`を付けます。インストーラの場合は、`sh`の前に`sudo`を付けます。
- サーバーにファイアウォールがあり、アプリがヘルパーを見つけられない場合は、自宅のネットワークからのTCPポート7459を許可します。

### MacまたはWindowsのDocker Desktop

- PlexはDockerの中ではなく、MacやPC上で直接動作します。それでも、ヘルパーはPlexを見つけられます。
- Macでは、コマンド1つで行うインストーラが使えます。Windowsでは、AIアシスタントを使うか、手動の手順で行ってください。
- アップロードフォルダは、MacやWindowsのパスで書きます（`/Users/you/Pictures/Camera Uploads`、`C:\Users\you\Pictures\Camera Uploads`など）。
- フォルダが共有されていないとDockerに表示された場合は、Docker DesktopのSettings > Resources > File sharing（設定 > リソース > ファイル共有）でフォルダを追加します。
- アップロードできるのは、Docker Desktopが動作していて、コンピュータがスリープしていないあいだだけです。Docker Desktopで、Settings > General > Start Docker Desktop when you sign in（サインイン時にDocker Desktopを起動）をオンにしてください。
- Windowsでは、ヘルパーを起動する前に、自宅のネットワークがプライベートに設定されていることを確認してください。Windows 11は初めて接続したネットワークをパブリックにします。また、下の項目のとおりに回答すると、スマートフォンからの接続はプライベート ネットワーク上でしか許可されません。Windows 11では、「設定」>「ネットワーク & インターネット」（Settings > Network & internet）を開き、「Wi-Fi」を選んで接続中のネットワークを選ぶか、「イーサネット」を選びます。「ネットワーク プロファイルの種類」で「プライベート ネットワーク」を選びます。プライベートは、自宅のネットワークにだけ選んでください。そのネットワーク上のほかのデバイスからPCが見つけられるようになります。
- WindowsからDocker Desktop Backendについて確認されたら、Private networks（プライベート ネットワーク）のチェックボックスだけにチェックが入っていることを確かめてから、Allow access（アクセスを許可する）を選びます。Windows 10の場合、自分でルールを追加する場合、Cancel（キャンセル）を選んでしまった場合は、[サーバーのファイアウォール](NETWORKING.md#サーバーのファイアウォール)を参照してください。
- Macでは、Dockerがネットワークからの接続を受け入れてよいかmacOSに確認されたら、許可してください。
- ヘルパーのログに`Running as root`と表示され、`doctor`に`The helper runs as root`というNOTEが表示されることがあります。Docker Desktopでは、どちらも無視してかまいません。Docker Desktopは、自分のユーザーとしてファイルを書き込むためです。
- Docker Desktopでは、ヘルパーからはすべてのスマートフォンが1つのアドレスに見えます。そのため、ヘルパーが1つのアドレスごとに設けている上限（同時接続24本、ペアリングの誤入力は1分あたり5回）を、すべてのスマートフォンで共有することになります。
- Windowsでは、コマンドをPowerShellで入力し、このページで`curl`となっているところは`curl.exe`を使います。

### docker runで同じことをする

次のコマンドは、Composeファイルと同じことを行います。ヘルパー用に作成したフォルダで実行してください。

```sh
docker run -d \
  --name phlix-camera-upload \
  --restart unless-stopped \
  -p 7459:7459 \
  --add-host=host.docker.internal:host-gateway \
  --security-opt no-new-privileges:true \
  --mount "type=bind,source=/mnt/media/Photos/Camera Uploads,target=/photos" \
  -v "$PWD/config:/config" \
  ghcr.io/jrl8085/phlix-camera-upload:1
```

`/mnt/media/Photos/Camera Uploads`は自分のアップロードフォルダに置き換えます。`--mount`を使うと、そのフォルダがない場合にDockerは起動を拒否します。`-v`の場合は、rootが所有する空のフォルダをDockerが作ってしまいます。

`--add-host`の行は残してください。Linuxでは、この行によって`host.docker.internal`という名前が使えるようになります。ヘルパーがPlexを最初に探すのは、この名前です。

## 写真の保存先

アップロードフォルダの中には、スマートフォンやタブレットごとのフォルダがあります。そのフォルダの中には、年ごとのフォルダと月ごとのフォルダがあります。

```
Camera Uploads/
  iPhone/
    2026/
      2026-11/
        IMG_1234.HEIC
```

- **デバイスのフォルダ**の名前は、デバイスのペアリング時に決まります。2台のデバイスが同じ名前を希望した場合、2台目には`iPhone 2`のように番号が付きます。もう一度ペアリングしたデバイスは、同じフォルダを使い続けます。ただし、Phlixで別の名前を入力した場合、そのデバイスの新しい写真はその名前のフォルダに入ります。
- **年と月**は、写真自体の日付（スマートフォンの現地時刻）から決まります。日付のない写真は、アップロードした日付で整理されます。
- **ファイル**の名前は、スマートフォン上の名前のままです。ヘルパーは、ファイルの更新日時も写真の日付に設定します。
- **同じ名前の異なる2枚の写真**は、両方とも保存されます。2枚目には番号が付きます（`IMG_1234 (2).HEIC`）。
- **2台のスマートフォンから届いた同じ写真**は、1回だけ保存されます。ヘルパーは、ファイル名ではなくファイルの内容を比較します。写真は、最初に送ったスマートフォンのフォルダに残ります。
- **写真がバックアップ済みとみなされる**のは、そのファイルがアップロードフォルダにある間だけです。ファイルやデバイスのフォルダ全体を削除した場合、その写真がまだデバイスにあれば、Phlixはもう一度アップロードします。Phlixはこれを、「カメラアップロード」画面を開いたときと、自宅でバックアップしている間にときどき確認します。
- **アップロードフォルダ内では、ファイルを好きなフォルダに整理**できます。ファイル名を変えなければ、Phlixはその場所でファイルを見つけます。デバイスのフォルダ名を変えても、ヘルパーはそのフォルダを引き続き使い、新しい写真もそこに入ります。ファイル名を変えたファイルや、アップロードフォルダの外に移したファイルは、もう一度アップロードされます。編集したファイルは、引き続きバックアップ済みとして数えられます。上書きされることは一切ありません。
- **アップロードのたびに、ファイルがすぐにアップロードフォルダから消えてしまう場合**、たとえばサーバー上のプログラムが新しいファイルを別の場所に移している場合、Phlixはそのファイルを最大3回まで送り直し、その後は「バックアップ不可」に表示します。フォルダを削除した写真が、そこに表示されることはありません。Phlixは毎回送り直します。そのため、そのようなプログラムが空にしたフォルダまで削除すると、3回までという上限が適用されず、Phlixはバックアップのたびに同じ写真をもう一度アップロードします。プログラムは、フォルダを残すように設定してください。スマートフォンを接続し直したときや、「バックアップ不可」に表示されていた写真が入っていたフォルダを削除したときも、Phlixはその写真をもう一度送ります。写真をサーバーに送りたくない場合は、「写真」アプリでその写真を非表示にしてください。Phlixは非表示の写真を一切アップロードしません。

ヘルパーが受け付けるのは次の種類のファイルで、それ以外はすべて拒否します。

- 写真：`jpg`、`jpeg`、`heic`、`heif`、`png`、`gif`、`tif`、`tiff`、`bmp`、`webp`、`avif`、`jxl`
- RAW写真：`dng`、`cr2`、`cr3`、`nef`、`arw`、`raf`、`orf`、`rw2`、`srw`、`pef`、`raw`
- ビデオ：`mov`、`mp4`、`m4v`、`avi`、`3gp`、`3g2`、`mts`、`m2ts`、`mkv`、`webm`

アップロードフォルダには、`.phlix-upload-tmp`という名前の隠しフォルダもあります。まだ受信中のアップロードが入っているので、そのままにしておいてください。

フォルダの構成を変えるには`PATH_TEMPLATE`を、受け付けるファイルの種類を増やすには`EXTRA_EXTENSIONS`を設定します。どちらも下の表にあります。

## 設定

ヘルパーは何も設定しなくても動作します。設定を変更するには、`docker-compose.yml`を開いて、`environment:`と変更したい設定の前にある`# `を削除し、もう一度`docker compose up -d`を実行します。

| 設定 | 既定値 | 内容 |
| --- | --- | --- |
| `PLEX_URL` | 空 | Plex Media Serverのアドレス（例：`http://192.168.1.10:32400`）。ポートのあとには何も書きません。ヘルパーは、書かれたとおりのアドレスを試したあと、httpとhttpsのもう一方でも試します。複数のアドレスを指定するには、カンマで区切ります。空の場合、ヘルパーはポート32400のPlexを4か所で探します。Dockerホスト（`host.docker.internal`）、コンテナのゲートウェイ、`127.0.0.1`、`plex`という名前のコンテナです。どの場所もまずhttpsで、次にhttpで試します。所有者がペアリングするときに、スマートフォンの有効期間の短いPlexサインイン情報をそのサーバーに提示するためです。どちらの場合も、ヘルパーはPlexの証明書を検証しません。ヘルパーが問い合わせる先を自分のサーバーだけに限定するには、これを設定してください。 |
| `PAIRING` | `auto` | ペアリングできる人。`auto`：Plexサーバーの所有者はコードなしでペアリングし、それ以外の人はペアリングコードを入力します。`code`：全員がコードを入力します。`plex`：Plexサーバーの所有者だけがペアリングできます。 |
| `PAIRING_CODE` | 空 | 自分で決めるペアリングコード。6文字以上の英字または数字にします。空の場合は、ヘルパーが初回起動時にコードを作成し、それを使い続けます。 |
| `NAME` | `Phlix Camera Upload` | アプリとステータスページに表示される、このヘルパーの名前。60文字以内。 |
| `PATH_TEMPLATE` | `{device}/{year}/{year}-{month}` | ヘルパーがアップロードフォルダ内に作るフォルダ。`{device}`、`{year}`、`{month}`、`{day}`を使えます。ドットで始まるフォルダ名は使えません。`/`だけにすると、すべてのファイルがアップロードフォルダの直下に入ります。デバイスのフォルダ名を変えてもヘルパーがそのフォルダを使い続けるのは、既定値のように`{device}`が独立したフォルダで、その前に日付がない場合だけです。 |
| `MIN_FREE_GB` | `2` | アップロード後にディスクの空き容量がこのGB数を下回る場合、ヘルパーはそのアップロードを拒否します。受信中のアップロードも計算に入れるため、複数のアップロードが同時に行われても、空き容量がこの値を下回ることはありません。0から1000000まで。 |
| `MAX_UPLOAD_GB` | `50` | ヘルパーが受け付ける1ファイルの最大サイズ（GB単位）。0.001から1000000まで。 |
| `EXTRA_EXTENSIONS` | 空 | 追加で受け付けるファイルの種類。カンマで区切ります（例：`insp,lrv`）。それぞれ1〜10文字の英字または数字です。 |
| `PUID` | 空 | ヘルパーがファイルを書き込むときのユーザーID。空の場合は、アップロードフォルダの所有者を使います。 |
| `PGID` | 空 | ヘルパーがファイルを書き込むときのグループID。空の場合は、アップロードフォルダのグループを使います。 |
| `UMASK` | `022` | 新しいファイルとフォルダに与えない権限。000から777までの8進数で指定します。`022`では、ほかのユーザーもファイルを読み取れます。`002`では、グループのユーザーがファイルを変更することもできます。 |
| `TLS` | `on` | `on`：ヘルパーはHTTPSで応答します。`off`：ヘルパーは暗号化なしのHTTPで応答します。PhlixはHTTPSでしか通信しないため、`off`は、ヘルパーの前段で自前のリバースプロキシがHTTPSを提供している場合にだけ使ってください。そのようなプロキシがない場合、`TLS`をオフにしたヘルパーはアプリから使えません。 |
| `TLS_CERT` | 空 | 自分で用意したPEM形式の証明書の、コンテナ内でのパス。`TLS_CERT`と`TLS_KEY`は一緒に設定します。どちらも空の場合は、ヘルパーが自分で証明書を作成します。 |
| `TLS_KEY` | 空 | `TLS_CERT`の秘密鍵の、コンテナ内でのパス。 |
| `LOG_LEVEL` | `INFO` | ログに出力する詳しさ。`debug`、`info`、`warning`、`error`のいずれかです。 |
| `PORT` | `7459` | コンテナ内でヘルパーが待ち受けるポート。1から65535まで。Dockerでは設定は不要です。サーバーで別のポートを使うには、`ports:`の行の最初の数字だけを変更します（例：`"8443:7459"`）。アプリが自動で探すのはポート7459なので、別のポートを使う場合は、アプリにヘルパーのアドレスを入力します。 |
| `BIND` | `0.0.0.0` | ヘルパーが待ち受けるIPv4アドレス。既定値は、すべてのアドレスを意味します。 |
| `UPLOAD_DIR` | `/photos` | アップロードの保存先となる、コンテナ内のフォルダ。Dockerではこれを変更せず、アップロードフォルダを`/photos`にマウントします。 |
| `CONFIG_DIR` | `/config` | ヘルパー自身のデータを置く、コンテナ内のフォルダ。Dockerではこれを変更せず、フォルダを`/config`にマウントします。 |

項目はあっても値が空の設定は、設定されていないものとして扱われ、ヘルパーは既定値を使います。そのため、Unraidのようにテンプレートに入力する画面では、どの欄を空のままにしてもかまいません。

イメージでは`PHLIX_CONTAINER=1`も設定されています。この設定があると、`/photos`と`/config`の両方が実際にマウントされていない限り、ヘルパーは起動を拒否します。`ALLOW_UNMOUNTED=1`で、このチェックをオフにできます。

## あとから変更する

### アップロードフォルダ

1. ヘルパーを停止します（`docker compose stop`）。
2. 新しいフォルダを作成します。このフォルダも、Plexの写真ライブラリのフォルダの中にある必要があります。
3. `docker-compose.yml`で、`source:`で始まる行を新しいフォルダに書き換えます。
4. `docker compose up -d`を実行します。

手順2と手順3のあいだに、古いアップロードフォルダの中身をすべて新しいフォルダに移し、中のフォルダ構成はそのまま保ってください。新しいフォルダにない写真は、スマートフォンからもう一度送られます。隠しフォルダ`.phlix-upload-tmp`も移してください。空のフォルダから始める場合は、その中に`.phlix-upload-tmp`という名前のフォルダを作成します。そうすると、スマートフォンはまだ残っているすべての写真をもう一度送ります。

### スマートフォンのフォルダ名

スマートフォンのフォルダ名を変えるには、サーバー上でフォルダ名を変更します。ヘルパーは新しい名前のフォルダを見つけ、そのスマートフォンの新しい写真をそこに入れます。または、Phlixで「接続を解除」を選び、接続し直して新しい名前を入力します。そうすると、新しい写真はその名前のフォルダに入り、すでにサーバーにある写真は元の場所に残ります。

### ポート

1. `docker-compose.yml`で、`ports:`の行の最初の数字だけを変更します（例：`"8443:7459"`）。
2. `docker compose up -d`を実行します。
3. 各スマートフォンに、新しいポートを含むヘルパーのアドレスを入力します（例：`https://192.168.1.10:8443`）。Phlixが自動で探すのはポート7459です。
   - まだペアリングしていないスマートフォンの場合：Phlixで「設定」>「カメラアップロード」を開き、「ヘルパーを探す」、「ヘルパーのアドレスを入力」の順にタップします。アドレスを入力し、「このアドレスを確認」をタップします。そのあとは、[iPhoneを接続する](#iphoneを接続する)の手順4から進めます。
   - ペアリング済みのスマートフォンは古いアドレスを使い続け、その「カメラアップロード」画面には新しいアドレスを入力する欄がありません。まずその画面で「接続を解除」を選び、そのあと上の項目のとおりに操作します。Plexサーバーの所有者以外の人は、ペアリングコードをもう一度入力します。フォルダ名はPhlixに表示されているままにしてください。そうすれば、スマートフォンのフォルダはそのまま使われ、同じものが二重にアップロードされることはありません。バックアップする項目をPhlixがもう一度尋ねますが、以前の選択があらかじめ設定されています。

### 別のマシン

1. 古いマシンでヘルパーを停止します（`docker compose down`）。
2. ヘルパーのフォルダ全体（`docker-compose.yml`と`config`フォルダ）を新しいマシンにコピーします。`config`フォルダにはペアリング情報と証明書が入っているので、スマートフォンのペアリングはそのまま保たれます。
3. 新しいマシンにアップロードフォルダがあることを確認します。パスが違う場合は、`source:`の行を書き換えます。
4. 新しいマシンで`docker compose up -d`を実行します。

Phlixは、Plexのアドレスでヘルパーを探します。ヘルパーがそこからなくなった場合は、各スマートフォンで、新しいマシンのアドレス（例：`https://192.168.1.30:7459`）を使って接続し直す必要があります。[ポート](#ポート)の手順3に従ってください。Plexが古いマシンに残る場合は、[NETWORKING.md](NETWORKING.md)の「Plexとは別のマシンで動くヘルパー」をお読みください。

コマンド1つで行うインストーラを使った場合は、`--photos`または`--port`を付けてもう一度実行すると、アップロードフォルダやポートを変更できます。ポートを変更したあとは、各スマートフォンで[ポート](#ポート)の手順3が必要です。

## アップデート

ヘルパーのフォルダで次のコマンドを実行するか、コマンド1つで行うインストーラをもう一度実行します。

```sh
docker compose pull
docker compose up -d
```

スマートフォンのペアリングはそのまま保たれます。アップデートで`config`フォルダが変更されることはありません。Composeファイルのタグ`:1`は、1.xのすべてのリリースに追従します。

Unraidでは、DockerタブのCheck for Updates（アップデートを確認）を使います。

### configフォルダ

`docker-compose.yml`の隣にある`config`フォルダは、ヘルパーの記憶にあたるものです。コンテナ内では`/config`です。次のものが入っています。

- ペアリング済みのスマートフォン
- スマートフォンが記憶している証明書
- ペアリングコード
- 各スマートフォンが送ったものの記録

写真は入っていません。残しておく価値があり、バックアップにも含めておく価値のあるフォルダです。

このフォルダがなくなると、ヘルパーは最初からやり直しになります。すべてのスマートフォンでペアリングし直す必要があり、スマートフォンは写真をもう一度送ります。各スマートフォンには、以前と同じフォルダ名を付けてください。これは、アップロードフォルダ内にあるそのスマートフォンのフォルダの名前です。そうすれば、ヘルパーが置いた場所にまだあるファイルは内容で識別され、二重に保存されることはありません。別のフォルダ名にすると、写真がもう一度保存されます。

## 削除

ヘルパーのフォルダで次のコマンドを実行します。

```sh
docker compose down
```

ヘルパーを削除しても、写真が削除されることはありません。ヘルパーが受け取ったものはすべて、アップロードフォルダに残ります。

ヘルパー自身のデータも削除するには、ヘルパー用に作成したフォルダを削除します。`config`フォルダは写真の所有者のものなので、`sudo`が必要になることがあります。アップロードフォルダ内の隠しフォルダ`.phlix-upload-tmp`も削除してかまいません。

## 監視

サインインなしで応答するアドレスが2つあります。どちらも秘密の情報は表示しません。

- `https://SERVER:7459/healthz`は、ヘルパーの動作中に`ok`を返します。Docker自体のヘルスチェックでも使われています。
- `https://SERVER:7459/api/v1/health`は、ステータスページの内容をJSONで返します。ヘルパーがアップロードフォルダに書き込めて、ディスクに十分な空きがあるときは、`ok`が`true`になります。そのほかのフィールドは、`version`、`uploadFolder`、`plex`、`pairing`、`tls`、`devices`、`files`です。

監視ツールでは、ヘルパー独自の証明書を受け入れるか、証明書の確認を省略する必要があります。

## プライバシーとセキュリティ

- **写真は自宅のネットワークの外に出ません**。スマートフォンは写真をサーバーに直接送ります。ヘルパーはインターネット上のどこにも接続しません。ヘルパーが接続するのは、自分のPlex Media Serverだけです。
- **接続は暗号化されます**。ヘルパーは初回起動時に独自の証明書を作成します。スマートフォンがペアリングすると、アプリはその証明書そのものを記憶します。それ以降、アプリはその証明書を示すサーバーとしか通信しません。
- **ペアリングには証明が必要です**。Plexサーバーの所有者はPlexを通じて証明し、ヘルパーがPlexトークンを保存することはありません。それ以外の人には、ペアリングコードが必要です。コードを当て推量で試す相手には、ヘルパーが待ち時間を課します。
- **トークンはハッシュ化して保存されます**。ペアリングしたスマートフォンには、それぞれ専用のトークンが発行されます。ヘルパーはそのハッシュだけを保存するため、ヘルパーのデータベースのコピーを使ってアップロードすることはできません。
- **何かが送り返されることは一切ありません**。保存されたファイルを一覧表示、読み取り、ダウンロード、削除する手段は、ヘルパーにはありません。ペアリングしたスマートフォンにできるのは、アップロードフォルダにファイルを追加することだけです。
- **ファイルはチェックされます**。ヘルパーが受け付けるのは、写真とビデオの種類のファイルだけです。すべてのファイル名とフォルダ名を無害化し、アップロードフォルダの外に書き込むことも、ファイルを上書きすることもありません。
- **ステータスページから情報が漏れることはありません**。ペアリングコードも、デバイス名も、ファイル名も表示しません。
- **ヘルパーはrootのままでは動作しません**。rootとして起動したあと、何かを提供する前に、アップロードフォルダの所有者、または`PUID`と`PGID`のユーザーに切り替わります。rootがアップロードフォルダを所有している場合、ヘルパーはrootのままになり、そのことをログと`doctor`で知らせます。
- **1台のデバイスがすべての枠を占有することはできません**。ヘルパーが許可する同時接続は、1つのアドレスから24本、全体で96本です。新しい接続には、TLSハンドシェイクに10秒、最初のリクエストの送信に20秒の猶予があります。そのあとは、75秒まで無通信のままでいられます。

ポート7459をインターネットに転送しないでください。ヘルパーは自宅のネットワーク用に作られており、Phlixがアップロードするのも自宅のネットワーク上だけです。

セキュリティ上の問題の報告方法は、[SECURITY.md](SECURITY.md)に記載しています。ペアリングしたスマートフォンが別のスマートフォンのファイルについて知りうることなど、既知のうえで受け入れている事項も挙げています。

## トラブルシューティング

まず、ヘルパー自身のチェックを実行します。インストールをテストし、問題があればその直し方を示します。

```sh
docker exec phlix-camera-upload python -m phlix_upload doctor
```

正常なヘルパーは、次のように答えます。

```
Phlix Camera Upload 1.0.3
OK       The helper is running on port 7459
OK       The upload folder /photos can be written to.
OK       224.5 GB free on the upload disk.
OK       Plex Media Server found: its owner can pair from Phlix without a code.
OK       1 paired, 33 files stored (25.9 MB).
NOTE     Pairing code: run `python -m phlix_upload code` the same way to see it.
Nothing needs fixing.
```

`NOTE`で始まる行はお知らせで、問題ではありません。`PROBLEM`で始まる行の次には、`Fix:`で始まる行があります。コンテナが動作していないとコマンドが答えた場合は、代わりにログを確認します（`docker logs phlix-camera-upload`）。

### アプリがヘルパーを見つけられない

まず上のチェックを実行してから、次の対処をこの順番で試してください。すべての項目は[NETWORKING.md](NETWORKING.md)にあります。

| 原因 | 対処 |
| --- | --- |
| ヘルパーが動作していないか、サーバーがスマートフォンからの接続を受け付けていない。 | 自宅の別のコンピュータで`https://SERVER:7459`を開きます。ページが開かない場合、問題はスマートフォンではなく、サーバーかネットワークにあります。 |
| スマートフォンが自宅のWi-Fiに接続していない。モバイルデータ通信、ゲストWi-Fi、VPNを使っている可能性があります。 | スマートフォンをサーバーと同じネットワークに接続します。Phlixは、モバイルデータ通信ではヘルパーを探しません。 |
| iOSによって、Phlixがネットワーク上のデバイスにアクセスできなくなっている。その場合、Phlixに“iOSによってPhlixのローカルネットワークへのアクセスが制限されています。「設定」でPhlixの「ローカルネットワーク」をオンにしてから、もう一度お試しください。”と表示されます。 | iPhoneで「設定」>「アプリ」>「Phlix」を開き、「ローカルネットワーク」をオンにします。 |
| ヘルパーがPlexとは別のアドレスやポートにある。 | アプリにヘルパーのアドレスを入力します（例：`https://192.168.1.10:7459`）。 |
| Phlixが1.0.21より古い。その場合、「設定」に「カメラアップロード」の行がありません。 | App StoreでPhlixを1.0.21以降にアップデートします。 |

### ブラウザでステータスページを開けない

| 原因 | 対処 |
| --- | --- |
| アドレスが`http://`で始まっている。 | `https://`を使います。 |
| ブラウザが証明書の警告で止まる。 | この警告は想定どおりです。「詳細設定」（Advanced）または「詳細を表示」（Show Details）を選んでから、ページに進みます。 |
| サーバーのファイアウォールがポートをブロックしている。 | 自宅のネットワークからのTCPポート7459を許可します。[NETWORKING.md](NETWORKING.md)をご覧ください。 |

### ステータスページに「Plex Media Server: Not found」と表示される

この場合も、スマートフォンはペアリングコードでペアリングできます。Plexが必要なのは、コードなしでのペアリングだけです。

| 原因 | 対処 |
| --- | --- |
| ヘルパーが起動した直後か、Plexがまだ動作していなかった。 | 1分ほど待ってからページを再読み込みし、数秒後にもう一度再読み込みします。ヘルパーは、誰かがページを開いたときにPlexを探し直し、その結果を次回の表示で示します。 |
| `host.docker.internal`の行なしでコンテナが起動された。 | Composeファイルをそのまま使います。`docker run`の場合は、`--add-host=host.docker.internal:host-gateway`を追加します。 |
| Plexが別のポートを使っている、または別のマシンで動作している。 | `PLEX_URL`にPlexのアドレスを設定します（例：`http://192.168.1.10:32400`）。 |
| サーバーのファイアウォールが、同じマシン上のPlexへのヘルパーの接続を妨げている。ヘルパーは、自宅のネットワークからではなく、自分のDockerネットワークからPlexに問い合わせます。そのため、自宅のネットワーク向けのルールでは通らず、`PLEX_URL`を設定しても変わりません。 | ペアリングコードでペアリングします。または、ヘルパーがPlexにアクセスできるようにします。その2つの方法は[サーバーのファイアウォール](NETWORKING.md#サーバーのファイアウォール)で紹介しています。 |

### ステータスページのPlexの行に「lets this helper in without signing in」と表示される

この場合も、スマートフォンはペアリングコードでペアリングできます。

| 原因 | 対処 |
| --- | --- |
| Plexの「認証なしで許可されているIPアドレスとネットワークのリスト」という設定に、ヘルパーのアドレスが含まれている。その場合、Plexはそのアドレスからの接続に相手を問わず応答するため、ヘルパーは所有者とそれ以外の人を区別できません。 | ペアリングコードでペアリングします。再びコードなしでペアリングできるようにするには、Plexの「設定」>「ネットワーク」にあるその設定から、Dockerのアドレスを外します。 |

### 写真がPlexに表示されない

まず、ファイルが届いているかどうかを確認します。ステータスページには`Files stored`が、Phlixの「カメラアップロード」画面にはアップロードされたものが表示されます。アップロードフォルダの中を見て確認することもできます。

| 原因 | 対処 |
| --- | --- |
| ファイルは届いているが、Plexがまだスキャンしていない。 | Plexで、「設定」>「ライブラリー」>「ライブラリーを自動的にスキャンする」をオンにします。今すぐスキャンするには、写真ライブラリのメニューを開いて「ライブラリーをスキャン」を選びます。 |
| ファイルは届いているが、アップロードフォルダがPlexの写真ライブラリのフォルダの中にない。 | Plexで、アップロードフォルダを写真ライブラリに追加します。「ライブラリを編集」、「フォルダを追加」の順に選びます。または、[アップロードフォルダを変更します](#アップロードフォルダ)。 |
| ファイルは届いているが、PlexがDockerで動作していて、そのフォルダがPlexコンテナにない。 | Plexコンテナに割り当てられているフォルダの中にあるアップロードフォルダを選びます。 |
| ファイルが届かない。 | スマートフォンが自宅のWi-Fiに接続している状態でPhlixを開き、「カメラアップロード」画面を確認します。最初の100件のアップロードを超えた分には、Phlix Proが必要です。 |
| ステータスページに`too little: uploads are paused`と表示される。 | ディスクの空き容量を増やすか、`MIN_FREE_GB`を下げます。 |

### ファイルの所有者が違うユーザーになる

| 原因 | 対処 |
| --- | --- |
| ヘルパーは、アップロードフォルダの所有者としてファイルを書き込みます。rootがそのフォルダを所有している場合、ファイルはrootのものになります。その場合、ログに`Running as root`と表示され、`doctor`には`The helper runs as root`というNOTEが表示されます。 | `PUID`と`PGID`に希望するユーザーとグループを設定してから、`docker compose up -d`を実行します。ユーザーの番号は、`id USERNAME`コマンドで表示できます。 |
| 変更前にアップロードされたファイルは、元の所有者のままになる。 | 次のコマンドで一度だけ変更します：`sudo chown -R USER:GROUP "/mnt/media/Photos/Camera Uploads"`。 |
| ほかのユーザーはファイルを読み取れるが、変更できない。 | `UMASK`を`002`に設定し、それらのユーザーがグループに入っていることを確認します。 |
| ステータスページに`The helper cannot write here`と表示される。 | ヘルパーを実行しているユーザーに、アップロードフォルダへの書き込みが許可されていません。フォルダの所有者か権限を変更するか、`PUID`と`PGID`を設定します。 |

### ヘルパーが停止し、ログに「it cannot use its own data folder」と表示される

| 原因 | 対処 |
| --- | --- |
| ヘルパーを実行しているユーザーに、`config`フォルダへの書き込みが許可されていない。ログの行には、そのユーザーとグループが番号で示されています。 | フォルダの所有者をそのユーザーにします。ヘルパーのフォルダで、ログの行にある2つの番号を使って`sudo chown -R USER:GROUP config`を実行します。または、`PUID`と`PGID`を`config`フォルダの所有者に設定します。そのあと`docker compose up -d`を実行します。 |
| サーバーがSELinuxを使っている。 | 次の項目をご覧ください。 |

### SELinuxを使うサーバーでヘルパーがフォルダを使えない

| 原因 | 対処 |
| --- | --- |
| Fedora、RHEL、Rocky Linuxなどのシステムでは、SELinuxが使われています。SELinuxは、コンテナ用のラベルが付いていないフォルダには、コンテナからのアクセスを一切許可しません。その場合、ログに`unable to open database file`とともに`it cannot use its own data folder`と表示されるか、ステータスページに`The helper cannot write here`と表示されます。 | 両方のフォルダにコンテナ用のラベルを付けます。ヘルパーのフォルダで、自分のアップロードフォルダを入れて次のコマンドを実行します：`sudo chcon -R -t container_file_t "/mnt/media/Photos/Camera Uploads" config`。そのあと`docker compose restart`を実行します。 |

### Docker Composeに「bind source path does not exist」と表示される

| 原因 | 対処 |
| --- | --- |
| `docker-compose.yml`に書いたアップロードフォルダが存在しないか、その行がまだ`/CHANGE/THIS`のままになっている。 | フォルダを作成し、パスのつづりを確認してから、もう一度`docker compose up -d`を実行します。 |
| フォルダは存在するが、DockerがSnap版である（Ubuntu Serverはインストール中にSnap版を勧めてきます）。Snap版のDockerからは、一部のフォルダしか見えません。また、ヘルパーの設定`no-new-privileges`を使うコンテナを起動できず、Dockerやログに`operation not permitted`と表示されます。 | `snap list docker`を実行します。dockerが一覧に表示されたら、Dockerを入れ替えます。まず`sudo snap remove docker`でSnapを削除します。これにより、このDockerが保持しているもの（コンテナ、イメージ、ボリューム）はすべて削除されます。アップロードフォルダとヘルパーのフォルダは残ります。Plexなど、ほかのプログラムもこのDockerで動いている場合は、削除する前に、それらを設定し直せることを確認してください。そのあと、[Docker公式の手順](https://docs.docker.com/engine/install/)でDockerをインストールし、もう一度`docker compose up -d`を実行します。 |

### Dockerに「port is already allocated」または「address already in use」と表示される

| 原因 | 対処 |
| --- | --- |
| Dockerがサーバーのポート7459を使えない。たいていは、別のプログラムか別のコンテナがそのポートを使っています。MacやWindows PCでは、Docker Desktopに`Ports are not available`と表示されます。 | ヘルパーに別のポートを割り当てます。`docker-compose.yml`の`ports:`の行で最初の数字だけを変更し（例：`"7460:7459"`）、もう一度`docker compose up -d`を実行します。コマンド1つで行うインストーラを使っている場合は、`--port 7460`を付けて再実行し、Composeファイルを置き換えるかどうか尋ねられたら`y`と答えます。そのあと、新しいポートを含むヘルパーのアドレスを各スマートフォンに設定します。[ポート](#ポート)を参照してください。 |

### コンテナがすぐに停止するか再起動を繰り返し、ログに「Nothing is mounted at /photos」と表示される

| 原因 | 対処 |
| --- | --- |
| `/photos`、`/config`、またはその両方にフォルダを割り当てずにコンテナが起動された。その場合、ヘルパーは起動を拒否します。そのままでは、アップロードがコンテナ内に保存され、次のアップデートで失われてしまうためです。 | Composeファイルや上の`docker run`コマンドのように、両方のフォルダを割り当ててヘルパーを起動します。 |
| 両方のフォルダがマウントされているのに、このメッセージが表示される。まれなケースです。Dockerが自身のデータをフォルダと同じディスクに置いていて、コンテナ用に別のファイルシステムを使っていない場合に起こることがあります。 | `docker-compose.yml`の`environment:`の下に`ALLOW_UNMOUNTED: "1"`の行を追加し、`docker compose up -d`を実行します。そのあと写真を1枚アップロードし、サーバー上のアップロードフォルダにそのファイルがあることを確認します。 |

### ヘルパーが起動せず、ログにアップロードフォルダが空だと表示される

| 原因 | 対処 |
| --- | --- |
| ヘルパーは以前アップロードフォルダに写真を保存していたのに、今はフォルダが空になっている。多くの場合、アップロードフォルダがある共有フォルダやディスクが、まだマウントされていません。その場合、ヘルパーはマウントされるまで待ちます。Dockerがヘルパーを何度も起動し直し、フォルダが戻るとヘルパーは自動的に起動します。 | 共有フォルダやディスクがマウントされていることを確認します。意図的にフォルダを空にした場合は、その中に`.phlix-upload-tmp`という名前のフォルダを作成します（例：`mkdir "/mnt/media/Photos/Camera Uploads/.phlix-upload-tmp"`）。そうするとヘルパーが起動し、スマートフォンはまだ残っているすべての写真をもう一度送ります。Unraidでは、Dockerタブでコンテナをもう一度起動します。 |

### ペアリングで試行回数が多すぎると表示される

| 原因 | 対処 |
| --- | --- |
| 1つのアドレスから、1分以内に5回誤った試行があった。誤った試行とは、間違ったペアリングコード、または拒否されたPlexサインインのことです。その場合、ヘルパーはそのアドレスを最大1分間待たせます。 | 1分待ちます。`docker exec phlix-camera-upload python -m phlix_upload code`でコードを表示し、もう一度入力します。 |
| すべてのアドレスを合わせて、10分以内に200回、誤ったペアリングコードが送られた。その場合、ヘルパーはコードによるペアリングを全員に対して最大10分間停止します。Plexを通じたペアリングは停止されません。 | 10分待ちます。Plexサーバーの所有者は、この間もコードなしでペアリングできます。誰が推測しているのかわからない場合は、ログで`Wrong pairing code from`を探します。 |

### スマートフォンにペアリングが解除されたと表示される

| 原因 | 対処 |
| --- | --- |
| 同じデバイスがもう一度ペアリングした。スマートフォンを復元したり設定し直したりしたあとなら、これは正常です。それまでのペアリングは使えなくなり、ログには、デバイスの名前と接続元のアドレスとともに`was already paired and has paired again from`と表示されます。 | スマートフォンをもう一度ペアリングします。家族の誰もそれをしていない場合は、ほかの誰かがペアリングコードを知っています。下の`new-code`コマンドで新しいコードを作成し、ヘルパーを再起動します。そのあとスマートフォンをもう一度ペアリングすると、もう一方のペアリングは終了します。 |
| `unpair`コマンドでデバイスのペアリングが解除された。 | スマートフォンをもう一度ペアリングします。 |
| ヘルパーが`config`フォルダを失い、新しい証明書を作成した。その場合、Phlixに「サーバーの識別情報が変わりました」と表示されます。 | Phlixで「カメラアップロード」画面を開き、「フォルダ」の行にある名前を書き留めます。「接続を解除」を選んでから接続し直し、同じフォルダ名を入力します。これをすべてのスマートフォンで行います。スマートフォンは写真をもう一度送りますが、ヘルパーが置いた場所、つまりスマートフォンのフォルダにまだあるファイルが、二重に保存されることはありません。[configフォルダ](#configフォルダ)をご覧ください。 |

### 「カメラアップロード」画面にメッセージが表示される

| Phlixの表示 | 対処 |
| --- | --- |
| 「ヘルパーがこのデバイスを認識しなくなりました」 | [スマートフォンにペアリングが解除されたと表示される](#スマートフォンにペアリングが解除されたと表示される)をご覧ください。Phlixはカメラアップロードをオフにしています。「カメラアップロード」画面で「接続を解除」を選んでから、接続し直してください。 |
| 「このデバイスの空き容量が残りわずかです」 | Phlixが各ファイルを送信できる状態にするには、スマートフォンに約300MBの空き容量が必要です。スマートフォンの空き容量を増やしてください。 |
| 「一部のアップロードが完了しませんでした」 | 次回の実行時に、Phlixがもう一度試します。今すぐ試すには、「接続を確認」をタップします。 |
| そのほかのメッセージ | セットアップガイドに、それぞれのメッセージがまとめられています：<https://phlixapp.com/camera-upload/#troubleshooting> |

## 管理コマンド

```sh
docker exec phlix-camera-upload python -m phlix_upload doctor
docker exec phlix-camera-upload python -m phlix_upload code
docker exec phlix-camera-upload python -m phlix_upload new-code
docker exec phlix-camera-upload python -m phlix_upload devices
docker exec phlix-camera-upload python -m phlix_upload unpair NAME
docker exec phlix-camera-upload python -m phlix_upload version
```

- `doctor`は、インストールを確認して問題の直し方を示します。ペアリングコードは表示しません。
- `code`は、ペアリングコードを表示します。
- `new-code`は、ペアリングコードを新しいものに置き換えます。新しいコードを使うには、ヘルパーを再起動します（`docker restart phlix-camera-upload`）。ペアリング済みのスマートフォンは、ペアリングされたままです。`PAIRING_CODE`を自分で設定している場合は、そちらでコードを変更します。
- `devices`は、すべてのデバイスを、フォルダ、ファイル数、ペアリングした日時、ヘルパーが最後に確認した日時とともに一覧表示します。
- `unpair NAME`は、ヘルパーにデバイスを忘れさせます。`NAME`には、`devices`に表示されるデバイスのフォルダ、名前、IDのいずれかを指定します。そのデバイスはアップロードできなくなりますが、ファイルは残ります。
- `version`は、ヘルパーのバージョンを表示します。

## 自分でビルドする

ヘルパーは素のPythonで書かれていて、標準ライブラリだけを使っています。プログラムは`phlix_upload/`に、テストは`tests/`にあります。テストには、Python 3.11以降と`openssl`コマンドが必要です。

```sh
git clone https://github.com/jrl8085/phlix-camera-upload.git
cd phlix-camera-upload
python3 -m unittest discover -s tests -t .
docker build -t phlix-camera-upload .
```

自分でビルドしたイメージを使うには、`docker-compose.yml`の`image:`の行を`phlix-camera-upload`に変更します。インストーラでは、変数で指定します（`PHLIX_CAMERA_UPLOAD_IMAGE=phlix-camera-upload sh install.sh`）。

動作中のヘルパーを端から端までテストするには、ヘルパーのアドレスとペアリングコードを指定してスモークテストを実行します。

```sh
sh scripts/smoke-test.sh https://localhost:7459 PAIRING-CODE
```

スモークテストは、`Smoke Test`と`Smoke Test 2`という名前の2台のデバイスとしてペアリングし、小さな画像を1枚アップロードします。最後に両方のペアリングを解除します。その画像は、アップロードフォルダ内の`Smoke Test`フォルダに残ります。

Dockerなしで実行できるチェックが、ほかに2つあります。

```sh
python3 scripts/check-docs.py
bash scripts/test-install.sh
```

1つ目は、このリポジトリの英語版ドキュメントをプログラムと照合します。2つ目は、Dockerの代わりになるダミーを使って`install.sh`を実行します。

`install.sh`には`docker-compose.yml`のコピーが、`skills/`のスキルには`SETUP-WITH-AI.md`の手順のコピーが入っています。この2つのファイルのどちらかを変更したら、コピーを作り直します。

```sh
python3 scripts/check-docs.py --sync
```

Claudeアプリ用にスキルをパッケージ化するには、`sh scripts/build-skill-zip.sh`を実行します。`dist/phlix-camera-upload-setup.zip`が作成されます。
