# セキュリティ

Phlix Camera Uploadは、Phlixアプリのベータ機能「カメラアップロード」用のヘルパーです。このページでは、そのセキュリティについて説明します。セットアップするには、セットアップガイドに従ってください：<https://phlixapp.com/camera-upload/>

## 問題の報告

セキュリティ上の問題は、公開のIssueではなく、非公開で報告してください。

1. このリポジトリのSecurityタブを開きます：<https://github.com/jrl8085/phlix-camera-upload/security>
2. Report a vulnerability（脆弱性を報告）を選びます。
3. 見つけた内容、再現方法、使っているヘルパーのバージョンを書きます。バージョンは`docker exec phlix-camera-upload python -m phlix_upload version`コマンドで表示できます。

修正が公開されるまで、GitHubは報告内容を報告者とメンテナーの間だけにとどめます。

## 対象範囲

- ヘルパー：このリポジトリの`phlix_upload/`フォルダにあるプログラム。
- そのDockerイメージ（`ghcr.io/jrl8085/phlix-camera-upload`）。
- ヘルパーをインストールするファイル：`install.sh`、`docker-compose.yml`、Unraidのテンプレート。

修正は、最新の1.xイメージ（タグ`:1`）に反映されます。

Phlixアプリ、Webサイトphlixapp.com、Plex Media Server、Dockerは、ここでの対象外です。アプリとWebサイトについては、<https://phlixapp.com/support/>をご利用ください。

## 安全のためのヘルパーのしくみ

ヘルパーは家庭内のネットワーク向けに作られています。インターネットからアクセスできる状態にしないでください。

**受け取るだけ**

- 保存されたファイルを読み出せるアドレスは、ヘルパーにはありません。ペアリングしたスマートフォンにできるのは、アップロードフォルダにファイルを追加することだけです。
- あるスマートフォンが、別のスマートフォンが送ったものを一覧表示することはできません。
- ステータスページとヘルスチェック用のアドレスには、ペアリングコード、トークン、デバイス名、ファイル名のどれも表示されません。

**接続**

- ヘルパーは、TLS 1.2以降のHTTPSで応答します。
- 初回起動時に、独自の証明書を作成します。アプリはペアリング時にその証明書のフィンガープリントを記憶し、それ以降はその証明書を示すサーバーとしか通信しません。

**ペアリング**

- Plexサーバーの所有者は、Plexを通じてペアリングします。アプリは、有効期間の短いPlexのサインイン情報を送ります。ヘルパーはそれを、見つけたPlexサーバーの、所有者だけが読み取れる2つのアドレスに提示し、リダイレクトには従いません。サインイン情報を保存することも、ログに書き込むこともありません。
- ヘルパーが自動でPlexを探すときは、途中でサインイン情報が読み取られないよう、まずhttpsを試します。Plexの証明書は検証しません。
- Plexがそれらのアドレスにサインインなしで応答する場合、サインイン情報は何の証明にもなりません。その場合、ヘルパーはPlexを通じたペアリングを拒否します。
- それ以外の人には、ペアリングコードが必要です。ヘルパーは安全な乱数源を使ってコードを作成し、定数時間で比較します。
- 1つのアドレスに認められる誤った試行は、1分あたり5回です。誤った試行とは、間違ったコード、または拒否されたPlexサインインのことです。
- すべてのアドレスを合わせて10分間に200回コードが間違えられると、コードによるペアリングが全員に対して一時停止されます。Plexを通じたペアリングが、この方法で停止されることはありません。

**トークン**

- ペアリングしたスマートフォンには、それぞれ256ビットのランダムなトークンが発行されます。
- ヘルパーが保存するのはトークンのSHA-256ハッシュだけで、ハッシュは定数時間で比較します。ヘルパーのデータベースのコピーを使ってアップロードすることはできません。
- スマートフォンのペアリングを解除すると、そのトークンはすぐに無効になります。ペアリング中のデバイスがもう一度ペアリングすると、それまでのトークンは使えなくなり、そのことがログに記録されます。

**ファイル**

- ヘルパーが受け付けるのは、写真とビデオの種類のファイルだけです。それ以外はすべて拒否するため、盗まれたトークンを使ってサーバーにプログラムを置くことはできません。
- スマートフォンから送られたファイル名とフォルダ名は、すべて無害化してからパスの一部にします。アップロードフォルダの外には何も書き込みません。
- ファイルは、使われていない名前で作成されます。すでにあるものが上書きされることはありません。
- ヘルパーは、スマートフォンが各アップロードに添えて送るSHA-256を確認し、壊れたアップロードは破棄します。
- アップロードにはサイズの上限があります。ヘルパーはディスクの一部を空けておき、受信中のアップロードも計算に入れるため、複数のアップロードが同時に行われてもディスクがいっぱいになることはありません。

**接続の制限**

- ヘルパーが許可する同時接続は、1つのアドレスから24本、全体で96本です。
- 新しい接続には、TLSハンドシェイクに10秒、最初のリクエストの送信に20秒の猶予があります。そのあとは、75秒まで無通信のままでいられます。

**プログラム**

- ヘルパーがrootとして起動するのは、アップロードフォルダの所有者、または`PUID`と`PGID`で指定したユーザーに切り替わるためだけです。切り替わる前には何も提供しません。
- Composeファイルでは、`no-new-privileges`を付けて起動します。
- ヘルパーが使うのはPythonの標準ライブラリだけです。イメージは、Alpine用の公式Pythonイメージに`openssl`パッケージを1つ追加したものです。
- ヘルパーは、Plexのパスワードもサインイン情報も保持しません。設定ページもサインインページもありません。

## 既知のうえで受け入れている事項

以下は不具合ではなく、意図した選択です。これらを超える問題があれば報告してください。

1. **1つのヘルパーを使うスマートフォンは、1つの世帯とみなします**。同一のファイルは1回だけ保存されます。そのため、ペアリングしたスマートフォンは、別のスマートフォンがあるファイルをすでにアップロードしたことと、そのファイルのサイズを知ることができます。ただしそのためには、同じファイルを持っているか、そのSHA-256を知っている必要があります。ファイルの保存場所を知ることも、ファイルを読み取ることもできません。
2. **ネットワーク上の誰でもステータスページを開けます**。表示されるのは、ヘルパーのバージョン、ディスクの容量と空き容量、Plexが見つかったかどうかとそのバージョン、ペアリング済みのデバイスの数、保存されたファイルの数とその合計サイズです。アプリが最初に問い合わせるアドレス`/api/v1/hello`は、ヘルパーの名前とPlexサーバーの識別子も返します。どちらにも、デバイス名、ファイル名、トークン、ペアリングコードは表示されません。
3. **ペアリングコードは世帯内の秘密です**。デバイスのIDは、そのデバイスとヘルパーだけが知っているランダムな値です。ペアリングコードとそのIDの両方を持っている人は、そのデバイスとしてペアリングできます。誰かが世帯を離れたら、`new-code`コマンドでコードを変更してください。
4. **`PLEX_URL`がない場合、ヘルパーはPlexとして応答したものを信頼します**。Dockerホスト、コンテナのゲートウェイ、`127.0.0.1`、`plex`という名前のコンテナを調べ、最初にPlexらしく応答したものを使います。自分のサーバーに固定するには、`PLEX_URL`を設定してください。
5. **rootがアップロードフォルダを所有している場合、ヘルパーはrootのままです**。そのことはログと`doctor`で知らせます。
6. **大量の接続があると、ヘルパーがふさがることがあります**。1つのアドレスからでも、24本の接続を占有できます。悪意のあるネットワークでは、それを防ぐ手立てはありません。これは家庭内のネットワーク用のヘルパーで、インターネット用ではありません。

## セキュリティレビューで試した攻撃

最初のリリースの前に、セキュリティレビューでヘルパーへの攻撃を試しました。次の点で、ヘルパーは攻撃に耐えました。

- スマートフォンが送るすべてのフィールドでの、パストラバーサルと異常な名前
- 写真とビデオの種類のファイルに限る制限と、ファイルを上書きしない決まり
- トークンとペアリングコードの比較
- リクエストのフレーミングと、保存されるすべての値に対するSQLインジェクション
