# ネットワーク：構成の方法と、アプリがヘルパーを見つけられないときの対処

ほとんどの家庭では、このページの内容は必要ありません。ヘルパーは初期状態のままで動作します。Phlixにヘルパーが見つからないと表示される場合や、サーバーのネットワークを特殊な構成にしている場合にお読みください。

カメラアップロードは、Phlixアプリのベータ機能です。画像付きの詳しい手順はすべて、セットアップガイドにあります：<https://phlixapp.com/camera-upload/>

## アプリがヘルパーを見つけるしくみ

- Phlixが自動で試すアドレスは1つだけです。自宅のネットワーク上にあるPlexサーバー自体のアドレスの、ポート7459です。
- それ以外のアドレスは、アプリに入力できます（例：`https://192.168.1.10:7459`）。
- PhlixはHTTPSでしか通信しません。
- Phlixは最初、スマートフォンが接続しているWi-Fiネットワークでヘルパーを探します。スマートフォンがペアリングすると、そのネットワークが自宅のネットワークになります。それ以降、Phlixはそのネットワークでだけヘルパーを探します。モバイルデータ通信、ほかのWi-Fiネットワーク、外部からのVPN経由で探すことはありません。
- カメラアップロードをオンにする前に、Phlixはヘルパーがあることを確認します。アプリでは「設定」>「カメラアップロード」>「ヘルパーを探す」です。ヘルパーがない場合、カメラアップロードはオフのままで、Phlixに「ヘルパーが見つかりません」と表示されます。ヘルパーがあり、スマートフォンのペアリングが済むと、画面に緑の点と「（ヘルパー名）に接続済み」が表示されます。

このページの`SERVER-IP`は、自宅のネットワーク上のサーバーのアドレス（`192.168.1.10`など）を表します。

## 最初の確認

まずサーバー上で、ヘルパー自身のチェックを実行します。何が問題で、どう直せばよいかが表示されます。

```sh
docker exec phlix-camera-upload python -m phlix_upload doctor
```

次に、以下の3つの手順をこの順番で行います。

1. 自宅の別のコンピュータから、ヘルパーに問い合わせます。

   ```sh
   curl -k https://SERVER-IP:7459/healthz
   ```

   答えは`ok`になるはずです。ヘルパーは独自の証明書を作成するため、`-k`が必要です。答えがない場合、問題はサーバーかネットワークにあります。[ネットワーク自体の問題](#ネットワーク自体の問題)に進んでください。答えが`ok`なら、サーバーに問題はありません。手順2に進みます。

2. スマートフォンがサーバーと同じWi-Fiに接続していることを確認します。ゲストWi-Fiやモバイルデータ通信は対象外です。

3. スマートフォンで「設定」>「プライバシーとセキュリティ」>「ローカルネットワーク」を開き、Phlixをオンにします。同じスイッチは「設定」>「アプリ」>「Phlix」にもあります。オンになっていないと、iOSによってPhlixは自宅のすべてのデバイスから遮断され、Phlixに「iOSによってPhlixのローカルネットワークへのアクセスが制限されています」と表示されます。

3つとも問題がないのにPhlixがヘルパーを見つけられない場合、ヘルパーはPlexのアドレスにはありません。アプリにヘルパーのアドレス（`https://SERVER-IP:7459`）を入力します。

## 構成の方法

それぞれの方法について、使う場面、`docker-compose.yml`で変更する箇所、アプリに入力する内容を説明します。変更したあとは、`docker compose up -d`を実行します。

### A. 既定の構成：Docker自身のネットワークと公開ポート

**使う場面**：Plexがヘルパーと同じマシンで、通常のプログラムとして、またはコンテナで動作している場合。`docker-compose.yml`は最初からこの構成になっています。

**変更点**：ありません。

**アプリでの操作**：入力するものはありません。

スマートフォンはサーバーのポート7459に接続し、Dockerがその接続をヘルパーに渡します。ヘルパーは、`host.docker.internal`という名前を使ってサーバー上のPlexにアクセスします。

### B. ホストネットワーク（Linux）

**使う場面**：サーバーのファイアウォールがコンテナからサーバー自体へのアクセスを止めているため、ステータスページに`Plex Media Server: Not found`と表示され続ける場合。または、Dockerにポートを転送させたくない場合。この方法はLinux専用で、Docker Desktopでは使えません。

**変更点**：

1. `ports:`と`- "7459:7459"`の2行を削除します。
2. `extra_hosts:`と`- "host.docker.internal:host-gateway"`の2行を削除します。
3. `restart: unless-stopped`の下に、同じインデントで`network_mode: host`の行を追加します。
4. `environment:`を有効にして、`PLEX_URL`を設定します。

   ```yaml
       network_mode: host
       environment:
         PLEX_URL: "http://127.0.0.1:32400"
   ```

これで、ヘルパーはサーバー自体のポート7459で待ち受けます。誰が接続できるかは、サーバーのファイアウォールで決まります。[サーバーのファイアウォール](#サーバーのファイアウォール)をご覧ください。別のポートを使うには、`environment:`の下で`PORT`を設定します。

**アプリでの操作**：入力するものはありません。

### C. 独自のDockerネットワーク上のコンテナで動くPlex

**使う場面**：Plexが自分で作成したDockerネットワーク上のコンテナで動作していて、Plexのポート32400がサーバーで公開されていない場合。ポート32400が公開されているか、Plexがホストネットワークを使っている場合は方法Aで動作するので、ここでの作業は必要ありません。

**変更点**：ヘルパーをPlexのネットワークに参加させ、Plexコンテナの名前をヘルパーに伝えます。

1. ネットワークの名前を調べます。Plexコンテナの名前が`plex`の場合は、次のようにします。

   ```sh
   docker inspect --format '{{range $name, $net := .NetworkSettings.Networks}}{{$name}} {{end}}' plex
   ```

2. `environment:`を有効にして、`PLEX_URL`にPlexコンテナの名前を設定します。

   ```yaml
       environment:
         PLEX_URL: "http://plex:32400"
   ```

3. ファイルの一番最後に次の行を追加し、`NETWORK-OF-PLEX`をネットワークの名前に置き換えます。

   ```yaml
   networks:
     default:
       name: NETWORK-OF-PLEX
       external: true
   ```

`ports:`の行は残してください。スマートフォンは引き続きサーバーのポート7459に接続します。

**アプリでの操作**：通常は必要ありません。Dockerネットワーク上のPlexコンテナは、Docker内部でしか使えないアドレスをPhlixに伝えることがあります。そのようなアドレスは、多くの場合`172.`で始まります。Phlixがヘルパーを見つけられない場合は、`https://SERVER-IP:7459`と入力します。

### D. ヘルパーに専用のアドレスを割り当てる（macvlan、ipvlan、Unraid br0）

**使う場面**：自宅のネットワーク上で、コンテナにそれぞれ専用のアドレスを割り当てている場合。Unraidでは、ネットワークタイプCustom: br0がこれにあたります。

**変更点**：Docker Composeで、ネットワーク名が`NAME-OF-YOUR-NETWORK`、アドレスが`192.168.1.50`の場合は次のとおりです。

1. `ports:`と`- "7459:7459"`の2行を削除します。ヘルパー専用のアドレスでは、すべてのポートが使えます。
2. `extra_hosts:`と`- "host.docker.internal:host-gateway"`の2行を削除します。
3. `restart: unless-stopped`の下に、同じインデントで次の行を追加します。

   ```yaml
       networks:
         lan:
           ipv4_address: 192.168.1.50
   ```

4. ファイルの一番最後に次の行を追加します。

   ```yaml
   networks:
     lan:
       name: NAME-OF-YOUR-NETWORK
       external: true
   ```

Unraidでは、テンプレートでNetwork TypeをCustom: br0に設定し、ヘルパーにFixed IP address（固定IPアドレス）を割り当てます。

専用のアドレスを持つコンテナは、自分が動作しているマシンと通信できません。これはmacvlanとipvlanのネットワークの決まりです。そのため、次のようになります。

- Plexにも専用のアドレスがある場合は、`PLEX_URL`にそのアドレスを設定します（例：`http://192.168.1.20:32400`）。
- Plexがサーバー上で直接動作している場合、ヘルパーはPlexにアクセスできません。その場合、スマートフォンはペアリングコードでペアリングします。Unraidでは、Settings > Docker > Host access to custom networks（カスタムネットワークへのホストアクセス）をオンにして、`PLEX_URL`にUnraidサーバーのアドレスを設定することもできます。

**アプリでの操作**：ヘルパー専用のアドレス（`https://192.168.1.50:7459`）を入力します。PhlixはPlexのアドレスで探しますが、ヘルパーはそこにはありません。

### E. Plexとは別のマシンで動くヘルパー

**使う場面**：Plexが動作しているマシンではDockerを動かせず、別のマシンなら動かせる場合。

ヘルパーのマシンから、Plexの写真ライブラリのフォルダに書き込めることが必要です。実際には、両方のマシンが使う共有フォルダにライブラリを置くことになります。

**変更点**：

1. アップロードフォルダ（`source:`で始まる行）は、ヘルパーのマシンから見たパスで書きます。
2. `environment:`を有効にして、`PLEX_URL`にPlexのマシンのアドレスを設定します。

   ```yaml
       environment:
         PLEX_URL: "http://192.168.1.20:32400"
   ```

**アプリでの操作**：ヘルパーのマシンのアドレス（`https://192.168.1.30:7459`）を入力します。

この構成では、2つの点が異なります。

- 共有フォルダ上の新しいファイルに、Plexが自動では気づかないことがあります。Plexで、「設定」>「ライブラリー」>「ライブラリーを定期的にスキャンする」もオンにしてください。
- ファイルの所有者は、Plexが読み取れるユーザーである必要があります。そうなっていない場合は、`PUID`と`PGID`を設定します。

### F. 別のポート

**使う場面**：サーバーでポート7459がすでに使われている場合。このとき、Dockerはヘルパーの起動時に`port is already allocated`または`address already in use`と表示します。

**変更点**：`ports:`の行の最初の数字だけを変更します。

```yaml
    ports:
      - "8443:7459"
```

ホストネットワーク（方法B）では、`ports:`の行はありません。代わりに、`environment:`の下で`PORT: "8443"`を設定します。

**アプリでの操作**：新しいポートを含むアドレス（`https://SERVER-IP:8443`）を入力します。

### G. リバースプロキシの背後に置く

**使う場面**：自宅でHTTPSを提供するリバースプロキシをすでに運用していて、ヘルパーをその背後に置きたい場合。通常の使い方ではプロキシは必要ありません。インターネットからヘルパーにアクセスする目的で、プロキシを使わないでください。Phlixがアップロードするのは自宅のネットワーク上だけです。

**変更点**：プロキシがHTTPSを提供し、その背後のヘルパーは暗号化なしのHTTPで通信します。

1. ヘルパーのポートにアクセスできるのを、このサーバーだけにします。`ports:`の行を次のように変更します。

   ```yaml
       ports:
         - "127.0.0.1:7459:7459"
   ```

2. `environment:`を有効にして、ヘルパー自身のHTTPSをオフにします。

   ```yaml
       environment:
         TLS: "off"
   ```

この2つの手順は、プロキシがサーバー上で直接動作している場合のものです。プロキシがコンテナで動作している場合は、ポートを一切公開しないでください。`ports:`の行を削除し、方法Cと同じようにヘルパーをプロキシのDockerネットワークに参加させ、プロキシからリクエストを`http://phlix-camera-upload:7459`に渡すようにします。

プロキシには、次の5つが必要です。

- HTTPSを提供すること。PhlixはHTTPSでしか通信しません。`TLS`がオフで、このようなプロキシもないヘルパーは、アプリから使えません。
- 大きなアップロードを許可すること。ビデオは数GBになることがあります。ヘルパーには独自の上限（`MAX_UPLOAD_GB`）があります。
- 時間のかかるアップロードが完了するまで待つこと。
- `Authorization`ヘッダーと、`X-Phlix-`で始まるすべてのヘッダーをヘルパーに渡すこと。
- `Content-Length`ヘッダーを残すこと。このヘッダーがないアップロードは、ヘルパーが拒否します。

nginxの場合：

```nginx
server {
    listen 443 ssl;
    server_name phlix-upload.home.example;

    ssl_certificate     /etc/nginx/certs/home.example.pem;
    ssl_certificate_key /etc/nginx/certs/home.example.key;

    # No limit on the size of an upload. The helper has its own limit.
    client_max_body_size 0;

    location / {
        proxy_pass http://127.0.0.1:7459;
        proxy_http_version 1.1;
        proxy_set_header Host $host;

        # Pass an upload on while it arrives, with no copy on the proxy's disk.
        proxy_request_buffering off;

        # Give a slow upload time.
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
```

Caddyの場合：

```
phlix-upload.home.example {
    reverse_proxy 127.0.0.1:7459
}
```

Caddyにはアップロードのサイズの上限がなく、すべてのヘッダーをそのまま渡します。

**アプリでの操作**：プロキシのアドレス（`https://phlix-upload.home.example`）を入力します。

プロキシの背後では、3つの点が異なります。

- スマートフォンに見えるのは、ヘルパーが作成した証明書ではなく、プロキシの証明書です。
- ヘルパーからは、すべてのスマートフォンがプロキシに見えます。そのため、1台のスマートフォンがペアリングを5回間違えると、すべてのスマートフォンが1分間待たされます。
- ヘルパーが1つのアドレスに許可する同時接続は24本です。プロキシの背後では、それをすべてのスマートフォンで共有します。

## ネットワーク自体の問題

### サーバーのファイアウォール

Linuxで方法Aを使う場合、ファイアウォールがオンでも、Dockerが公開ポートを自動で開きます。ファイアウォールが関係するのは、ホストネットワーク（方法B）の場合、Docker Desktopの場合、独自のファイアウォールを持つNASの場合です。

自宅のネットワークからのTCPポート7459を許可します。以下の例は、自宅のネットワークが`192.168.1.0/24`の場合です。

- **ufw**（Ubuntu、Debian）：

  ```sh
  sudo ufw allow from 192.168.1.0/24 to any port 7459 proto tcp
  ```

- **firewalld**（Fedora、RHEL、Rocky Linux）：

  ```sh
  sudo firewall-cmd --permanent --add-port=7459/tcp
  sudo firewall-cmd --reload
  ```

- **Windows Defender ファイアウォール**：Windows 11は初めて接続したネットワークをパブリックにします。パブリック ネットワークでは、プライベート ネットワーク用のルールは何の効果もありません。そのため、まず自宅のネットワークがプライベートに設定されていることを確認します。Windows 11では、「設定」>「ネットワーク & インターネット」（Settings > Network & internet）を開き、「Wi-Fi」を選んで接続中のネットワークを選ぶか、「イーサネット」を選びます。「ネットワーク プロファイルの種類」で「プライベート ネットワーク」を選びます。Windows 10では、Settings > Network & Internet（設定 > ネットワークとインターネット）を開き、Wi-FiまたはEthernet（イーサネット）を選んでから自分のネットワークを選び、Network profile（ネットワーク プロファイル）でPrivate（プライベート）を選びます。プライベートは、自宅のネットワークにだけ選んでください。そのネットワーク上のほかのデバイスからPCが見つけられるようになります。各ネットワークの種類を確認するには、PowerShellで`Get-NetConnectionProfile`を実行し、`NetworkCategory`を見ます。

  次に、プライベート ネットワークでだけDocker Desktopを許可します。Docker Desktopは、公開されているすべてのポートへの接続を1つのプログラム`com.docker.backend.exe`で受け付けます。Windowsではこのプログラムが「Docker Desktop Backend」と表示されます。通常、ヘルパーを初めて起動したときに、このプログラムについてWindowsから確認されます。Private networks（プライベート ネットワーク）のチェックボックスだけにチェックが入っていることを確かめてから、Allow access（アクセスを許可する）を選びます。Windowsから確認されない場合は、自分でルールを追加します。管理者としてPowerShellで次を実行してください。このルールは、PCと同じサブネット上のデバイスだけを、ネットワークがプライベートのときだけ通します。

  ```powershell
  New-NetFirewallRule -DisplayName "Phlix Camera Upload" -Direction Inbound -Protocol TCP -LocalPort 7459 -RemoteAddress LocalSubnet -Action Allow -Profile Private
  ```

  スマートフォンが専用のVLANなど別のサブネットにある場合は、`LocalSubnet`の代わりにそのサブネットを書きます（例：`192.168.20.0/24`）。

  Windowsは、Docker Desktop Backendについての最初の回答を記憶します。Cancel（キャンセル）を選んだり、ウィンドウを閉じたりすると、それ以降はこのプログラムをブロックします。ブロックのルールは、上のルールも含め、どの許可ルールよりも優先されます。パブリック ネットワークだけを許可する回答をした場合も、通常は、プライベートに設定した自宅のネットワーク上でスマートフォンからヘルパーにアクセスできません。もう一度確認を表示させるには、管理者としてPowerShellで次を実行します。

  ```powershell
  Remove-NetFirewallRule -DisplayName "Docker Desktop Backend"
  ```

  そのあと、Docker Desktopを終了して再び起動し、上記のとおりに回答します。古いバージョンのDocker Desktopでは、このルールの名前が`com.docker.backend.exe`でした。それでもスマートフォンからヘルパーにアクセスできない場合は、`Docker Desktop Backend`の代わりにその名前を指定して、コマンドをもう一度実行します。

- **macOS**：ファイアウォールがオンの場合は、「システム設定」>「ネットワーク」>「ファイアウォール」>「オプション」で、Dockerへの受信接続を許可します。
- **Synology**：ファイアウォールがオンの場合は、Control Panel > Security > Firewall > Edit Rules（コントロールパネル > セキュリティ > ファイアウォール > ルールの編集）でルールを追加します。ポートはCustom（カスタム）でTCP 7459、アクションはAllow（許可）です。
- **QNAP**：QuFirewallがオンの場合は、QuFirewall > Firewall Profiles（ファイアウォール プロファイル）を開き、使用中のプロファイルを編集します。Add Rule（ルールの追加）を選びます。Permission（権限）をAllow（許可）に、Source（ソース）をIPにして、自宅のネットワーク（`192.168.1.0/24`）を指定します。Protocol（プロトコル）をTCPに、Port（ポート）を7459にして、Apply（適用）を選びます。すべてを拒否するルールがある場合は、このルールをそれより上に置き、もう一度Apply（適用）を選んでから、Yes（はい）を選びます。
- **Unraid**：Unraidには独自のファイアウォールがないため、開くものはありません。

ファイアウォールが、同じマシン上のPlexへのヘルパーの接続を妨げることもあります。この場合、ステータスページには`Plex Media Server: Not found`と表示されます。ヘルパーは、自宅のネットワークからではなく、自分のDockerネットワークからPlexに問い合わせます。そのため、自宅のネットワーク向けのルールでは通らず、`PLEX_URL`を設定しても変わりません。次のいずれかを選んでください。

- ペアリングコードでペアリングします。これでも同じように使え、ファイアウォールもそのままにできます。
- ホストネットワークを使います（[方法B](#b-ホストネットワークlinux)）。この場合、ヘルパーはサーバー自体の`127.0.0.1`でPlexに問い合わせ、ファイアウォールは通常これを通します。方法Bでは、誰がポート7459にアクセスできるかもファイアウォールで決まります。上記のとおり、自宅のネットワークからのアクセスを許可してください。
- ヘルパーのDockerネットワークからポート32400にだけアクセスできるようにします。次のコマンドで、ネットワークの範囲（例：`172.18.0.0/16`）を確認できます。

  ```sh
  docker network inspect --format '{{range .IPAM.Config}}{{.Subnet}} {{end}}' phlix-camera-upload_default
  ```

  ネットワークの名前は、ヘルパーのフォルダの名前から付けられます。そのようなネットワークはないとDockerに表示された場合は、`phlix-camera-upload`の代わりに自分のフォルダの名前を書きます。`docker run`でヘルパーを起動した場合、ネットワークは`bridge`です。次に、その範囲からTCPポート32400へのアクセスを許可します。ufwの場合は、`RANGE`の代わりにその範囲を書きます。

  ```sh
  sudo ufw allow from RANGE to any port 32400 proto tcp
  ```

  Synologyでは、Control Panel > Security > Firewall > Edit Rules（コントロールパネル > セキュリティ > ファイアウォール > ルールの編集）でルールを追加します。ポートはCustom（カスタム）でTCP 32400、送信元IPはSpecific IP（特定のIP）でその範囲を指定し、アクションはAllow（許可）です。拒否するルールがある場合は、それより上にドラッグします。`docker compose down`のあと、次に起動したときに、Dockerがヘルパーに別の範囲を割り当てることがあります。その場合は、範囲をもう一度確認してください。

### ゲストWi-Fiとクライアント分離

ゲストWi-Fiは、接続したデバイスを家庭内のほかの機器から切り離します。スマートフォンはメインのWi-Fiに接続してください。

ルーターやアクセスポイントによっては、メインのWi-Fiのデバイス同士も切り離すものがあります。この設定は、クライアント分離（client isolation）、APアイソレーション（AP isolation）、ワイヤレス分離（wireless isolation）などと呼ばれます。スマートフォンが使うネットワークでは、この設定をオフにしてください。

### VLAN

スマートフォンとサーバーが別々のVLANにある場合、その間を何が通れるかはルーターが決めます。スマートフォンのVLANからサーバーへのTCPポート7459を許可します。そのうえでPhlixがヘルパーを自動で見つけられない場合は、アプリにサーバーのアドレスを入力します。

### スマートフォンのVPNアプリ

VPNアプリによっては、自宅のネットワーク宛ての通信も含めて、すべての通信をVPN経由で送るものがあります。その場合、Phlixはヘルパーにアクセスできません。自宅ではVPNをオフにするか、VPNアプリでローカルネットワークへのアクセスを許可する設定をオンにしてください。

外部から自宅に接続するVPNは役に立ちません。Phlixがアップロードするのは自宅のWi-Fi上だけです。

### サーバーのアドレスが変わった場合

ほとんどのルーターはアドレスを期限付きで割り当てるため、サーバーに新しいアドレスが割り当てられることがあります。そうなると、Phlixがヘルパーを見失うことがあります。アプリにアドレスを入力していた場合は特にそうです。サーバーには固定のアドレスを割り当ててください。ルーターで、サーバーのDHCP予約を設定します。

アドレスが変わると、ペアリング済みのスマートフォンは、Plexの新しいアドレスでヘルパーを自動で探し直します。それでもヘルパーが見つからない場合（たとえば、セットアップ時にアドレスを入力していた場合）は、スマートフォンを接続し直す必要があります。「カメラアップロード」画面で「接続を解除」を選び、「ヘルパーを探す」をタップして、もう一度接続します。フォルダ名はPhlixに表示されているままにしてください。そうすれば、スマートフォンのフォルダはそのまま使われ、同じものが二重にアップロードされることはありません。バックアップする項目をPhlixがもう一度尋ねますが、以前の選択があらかじめ設定されています。

### ルーターの後ろに、もう1台ルーターがある場合

自宅で1台目のルーターの後ろに2台目のルーターがある場合、それぞれが別のネットワークを作ります。これは二重NATとも呼ばれます。スマートフォンとサーバーを同じネットワークに置いてください。または、2台目のルーターをアクセスポイントモード（ブリッジモードとも呼ばれます）にして、自宅のネットワークを1つにします。
