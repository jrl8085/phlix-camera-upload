# 安全性

Phlix Camera Upload 是「相機上傳」的輔助程式，「相機上傳」是 Phlix App 的一項測試版功能。本頁說明它的安全性。若要安裝，請依照設定指南操作：<https://phlixapp.com/camera-upload/>

## 回報問題

請私下回報安全性問題，不要發在公開的 issue 中。

1. 開啟這個存放庫的「Security」分頁：<https://github.com/jrl8085/phlix-camera-upload/security>
2. 選擇「Report a vulnerability」（回報弱點）。
3. 說明你發現了什麼、如何重現，以及你使用的輔助程式版本。執行指令 `docker exec phlix-camera-upload python -m phlix_upload version` 就會顯示版本。

在修正釋出之前，GitHub 只會讓你和維護者看到這份回報。

## 涵蓋範圍

- 輔助程式：這個存放庫中 `phlix_upload/` 資料夾裡的程式。
- 它的 Docker 映像檔 `ghcr.io/jrl8085/phlix-camera-upload`。
- 用來安裝它的檔案：`install.sh`、`docker-compose.yml` 和 Unraid 範本。

修正會放進最新的 1.x 映像檔，也就是標籤 `:1`。

不屬於這裡的範圍：Phlix App、網站 phlixapp.com、Plex Media Server 和 Docker。App 和網站的問題，請使用 <https://phlixapp.com/support/>。

## 輔助程式的安全設計

輔助程式是為家用網路設計的，不應該能從網際網路連到它。

**它只負責接收。**

- 輔助程式沒有任何位址會把已儲存的檔案讀回去。已配對的手機只能把檔案加進上傳資料夾，其他什麼都不能做。
- 一支手機無法列出另一支手機傳送過的內容。
- 狀態頁面和健康檢查位址都不會顯示配對碼、權杖、裝置名稱或檔案名稱。

**連線。**

- 輔助程式以 TLS 1.2 或更新版本提供 HTTPS。
- 首次啟動時，它會自行建立憑證。App 在配對時會記住這個憑證的指紋，之後只會和出示這個憑證的伺服器通訊。

**配對。**

- Plex 伺服器的擁有者透過 Plex 配對。App 會送出一份短期有效的 Plex 登入資訊。輔助程式會把它出示給自己找到的 Plex 伺服器，用在兩個只有擁有者能讀取的位址上，而且不會跟隨任何重新導向。它絕不會儲存這份登入資訊，也絕不會把它寫進日誌。
- 輔助程式自行尋找 Plex 時，會先嘗試 https，以免登入資訊在傳輸途中被讀取。它不會檢查 Plex 的憑證。
- 如果 Plex 不需要登入資訊就回應這兩個位址，登入資訊就證明不了任何事。這時輔助程式會拒絕透過 Plex 配對。
- 其他人都需要配對碼。輔助程式以安全的隨機來源產生配對碼，並以常數時間比對。
- 每個位址每分鐘可以錯誤嘗試 5 次。錯誤嘗試是指輸入了錯誤的配對碼，或 Plex 登入資訊遭到拒絕。
- 所有位址加起來在十分鐘內輸入錯誤的配對碼達 200 次後，所有人都會暫時無法用配對碼配對。透過 Plex 配對則絕不會因此暫停。

**權杖。**

- 每支已配對的手機都會取得自己專屬的 256 位元隨機權杖。
- 輔助程式只儲存權杖的 SHA-256 雜湊值，並以常數時間比對雜湊值。就算拿到輔助程式資料庫的副本，也無法用來上傳。
- 取消手機的配對會立即讓它的權杖失效。仍在配對狀態的裝置再次配對時，它先前的權杖就會失效，日誌也會記錄這件事。

**檔案。**

- 輔助程式只接受照片和影片的檔案類型，其他一律拒絕，因此即使權杖遭竊，也無法用來把程式放到伺服器上。
- 手機送來的每個檔案名稱和資料夾名稱，都會先經過清理，才會成為路徑的一部分。上傳資料夾以外的地方一律不會寫入。
- 檔案一律以尚未使用的名稱建立。既有的任何檔案都不會被覆寫。
- 輔助程式會檢查手機隨每次上傳送來的 SHA-256，並丟棄損壞的上傳。
- 上傳有大小上限。輔助程式會保留一部分磁碟空間，並把仍在傳輸中的上傳一併計入，因此即使同時進行多筆上傳，也無法塞滿磁碟。
- 為了告訴手機它的哪些照片還在，輔助程式會讀取上傳資料夾中的名稱；對於可能是其中某張照片被移動後的檔案，還會讀取它的大小、日期或內容。輔助程式只會以該手機自己的照片 id 回答，絕不會回傳檔案或檔案清單。

**連線數量。**

- 輔助程式允許單一位址同時建立 24 個連線，總計 96 個。
- 新連線有 10 秒完成 TLS 交握，並有 20 秒送出第一個請求。之後，連線最多可以 75 秒不傳送任何資料。

**程式本身。**

- 輔助程式以 root 身分啟動，只是為了切換成上傳資料夾的擁有者，或切換成 `PUID` 和 `PGID` 指定的使用者。在此之前，它不提供任何服務。
- Compose 檔案以 `no-new-privileges` 啟動它。
- 輔助程式只使用 Python 標準函式庫，不依賴其他任何東西。映像檔是官方的 Alpine 版 Python 映像檔，只額外加了一個套件：`openssl`。
- 輔助程式不保存任何 Plex 密碼，也不保存任何 Plex 登入資訊。它沒有設定頁面，也沒有登入頁面。

## 已知並接受的事項

這些是刻意的選擇，不是缺陷。超出這些範圍的問題，請回報。

1. **同一個輔助程式的手機屬於同一個家庭**。相同的檔案只會儲存一次。因此，已配對的手機可以得知另一支手機已經上傳過某個檔案，以及該檔案有多大。前提是它必須持有同一個檔案，或知道該檔案的 SHA-256。手機也可以透過名稱、大小和日期得知這件事：當它傳送的某個檔案已不在輔助程式存放的位置時，輔助程式會在整個上傳資料夾中尋找名稱、大小和日期都相同的檔案，其他手機的資料夾也包括在內。無論是哪一種情況，手機都無法得知檔案存放在哪裡，也無法讀取檔案。
2. **網路上的任何人都能開啟狀態頁面**。頁面會顯示輔助程式的版本、磁碟大小與可用空間、是否找到 Plex 及其版本、已配對的裝置數量，以及已儲存的檔案數量與總大小。App 第一個詢問的位址 `/api/v1/hello` 還會提供輔助程式的名稱和 Plex 伺服器的識別碼。這些都不會顯示裝置名稱、檔案名稱、權杖或配對碼。
3. **配對碼是家庭內的祕密**。裝置的 id 是只有該裝置和輔助程式知道的隨機值。同時握有配對碼和那個 id 的人，就能以那台裝置的身分配對。有人離開這個家庭時，請用 `new-code` 指令更換配對碼。
4. **沒有設定 `PLEX_URL` 時，輔助程式會信任以 Plex 身分回應的對象**。它會查看 Docker 主機、容器的閘道、`127.0.0.1` 和名為 `plex` 的容器，並採用第一個像 Plex 一樣回應的對象。設定 `PLEX_URL`，就能把它固定在你的伺服器上。
5. **如果上傳資料夾的擁有者是 root，輔助程式就會維持 root 身分**。它會在日誌和 `doctor` 中說明這一點。
6. **繁忙的網路可能讓輔助程式忙不過來**。單一位址仍然可以佔用 24 個連線。在充滿惡意的網路上，沒有任何東西能完全避免這種情況。這是給家用網路用的輔助程式，不是給網際網路用的。

## 安全審查攻擊過的項目

在首次發行之前，一次安全審查曾對輔助程式發動攻擊。以下項目都守住了：

- 手機傳送的每個欄位中的路徑穿越（path traversal）與奇怪的名稱；
- 只接受照片和影片檔案類型的限制，以及不覆寫任何檔案的規則；
- 權杖與配對碼的比對；
- 請求的訊息分界（framing），以及每個要儲存的值中夾帶的 SQL。
